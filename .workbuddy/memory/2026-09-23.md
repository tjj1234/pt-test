## GTM HTTP 请求标签 403 排障（sGTM → collect 接口）

**现象**：GTM Server 容器的 HTTP 请求标签 POST 到 `https://pt-test.skyjilygao.cn/api/v1/collect/wh_powertokens_001`，失败 19 次，全部 403。

**根因**：GTM 请求头 `x-pt-webhook-secret` 填的是 **sha256 哈希值**（`7263ea80...d58`，还带了 `+ 060d08` 拼接），而服务端 `secretMatches`（server.js）逻辑是 `sha256(请求头值) == 库里 secret_hash`。发哈希等于做了两次哈希，必然不匹配 → 403。

**实测证据**（127.0.0.1:8095）：发哈希值 → 403 Forbidden；发原始 secret `b376a835...d58` → 200 `{"ok":true}`。

**修复方法**：GTM 标签请求头改为填**原始 secret**（`b376a8359e51cd4d5d3f1808f5df04d51a123fa76379642ce20725a5b5365d58`），去掉任何拼接表达式。另注意请求正文目前是写死的测试值（event_id/timestamp 固定），应改用 GTM 变量映射真实事件数据，否则每条事件入库都一样。

## GTM 第二轮失败：400 空请求体 + 字段约束未满足（13:43 排障）

**现象**：用户把 event_id（`playground_submit_126fc008-...`）、client_id、trigger_from、user_id 全放在请求头里，Body 留空，触发失败。日志 12:28 起连续 400。

**根因（日志实锤，错误码 `FST_ERR_CTP_EMPTY_JSON_BODY`）**：
1. **直接原因**：`Content-Type: application/json` 但 body 为空 → Fastify 400。数据放 Headers 服务端不读（只认 `x-pt-webhook-secret` + body）。
2. **潜在两坑（加 body 后也会撞）**：
   - `event_id` 必须纯 UUID（`validate.js` UUID_PATTERN），`playground_submit_` 前缀不合格；
   - `event_name` 必须在白名单（validate.js `EVENT_WHITELIST`：visit/signup/key_created/model_call/recharge/auto_recharge_toggle），`playground_submit` 不在。

**产出**：`analytics/docs/gtm_collect_tag_template.md` 已补「服务端三件套硬性校验」一节（event_id UUID / event_name 白名单 / timestamp 毫秒 / body 不可空）。

## GTM 第三轮失败：JSON 语法错误（13:52 排障）

**现象**：用户加了 Body，但连续 400，日志错误为 `SyntaxError: Unexpected token ','` —— 发出的 JSON 是 `"event_id": ,`（变量解析为空）或 `"event_id": playground`（变量值未加引号注入）。

**根因（3 处 GTM 配置问题）**：
1. Body 模板里变量引用**没包双引号**：`"event_id": {{EDV – event_id}}` → 变量值原样注入破坏 JSON。必须写 `"event_id": "{{EDV – event_id}}"`。
2. `EDV – event_id` 变量在部分事件上**解析为空** → `"event_id": ,`。
3. secret 头的值末尾**误粘了 `EDV – event_id` 变量**（`"5365d58" EDV – event_id`），JSON 修好后会变 403；另有一个空 key 头 `{key:"", value:"EDV – client_id"}` 应删。
4. `event_name: ""` 空串不在白名单，JSON 修好后也会 400。

## 11:58 用公网域名验证 collect 接口（curl → Cloudflare → 8095）

**结果**：
