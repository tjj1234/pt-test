## 2. 安装与配置

### 2.1 当前可复现入口

仓库根目录没有统一 `package.json`。在隔离检出的目标版本中分别安装 analytics 与 shell；shell 使用锁文件安装，避免隐式漂移：

```bash
# 仓库根目录执行
npm ci --prefix shell
npm install --prefix analytics
# 分别在两个终端启动；先通过受控方式注入该环境配置
node analytics/start.cjs
node shell/server.cjs
```

analytics 安装方式沿用当前 README；正式发布包必须固化其锁文件和可复现安装方式。当前 package 声明 Node >=18，CI 验证 Node 20/22；这不是对所有版本与操作系统的兼容保证。上线须选择仍受支持且实测通过的 Node 版本，记录具体版本和 OS，不直接采用旧 Windows 机器路径。

本地默认 shell `127.0.0.1:8098`、analytics `127.0.0.1:8095`。`/healthz` 仅证明服务探活，不证明 Google、数据库恢复、DSH、模型或工具可用。外部统一经 HTTPS 反向代理访问；前端和 API 可分开构建与部署后仍保持同源。SSE 代理需实测持续输出、断开、重连、取消及长耗时任务，不能仅以普通 GET 通过验收。

### 2.2 已存在的关键配置

| 配置 | 当前用途／操作约束 |
|---|---|
| `DSH_JS` | 可显式指定 DSH `bin.js`；发布时核对实际解析到的版本，禁止悄悄使用开发者的全局安装 |
| `PT_SHELL_PORT`、`PT_DASH_PORT`、`PT_LISTEN_HOST` | 服务监听配置；容器需区分业务壳监听与 DSH 内部监听，DSH 不得暴露公网 |
| `PT_DB_DIR`、`PT_MASTER_KEY_FILE` | PGlite 数据及主密钥位置；应位于受控持久卷，不能随代码发布覆盖 |
| `PT_PG_DSN` 或 `PT_PG_HOST`／`PT_PG_USER`／`PT_PG_DATABASE` 等 | 检测到 PG 配置时切换真实 PG；须检查驱动、TLS、账号权限与目标库，防止误连生产 |
| `PT_COOKIE_SECURE=1` | HTTPS 环境启用安全 Cookie 与现有 HSTS 逻辑；本地 HTTP 与生产配置分开 |
| `TRUST_PROXY` | 仅在可信代理边界内开启，代理必须覆盖客户端可伪造的转发头 |
| `PT_DASH_TOKEN`、`PT_DASH_WEBHOOK_SECRET`、`PT_DASH_INTERNAL_KEY` | 看板／内部链路凭据；按实际入口配置，不公开、不作为用户模型 Key，不因旧 README 建议而在生产直接 reseed |
| `PT_DOC_UPLOAD_MB`、`PT_DOC_CONTEXT_CHARS`、`PT_MEDIA_UPLOAD_MB`、`PT_UPLOAD_QUOTA_MB` | 现有文件与上下文限额；扩展格式需要额外解析、OCR、解压资源边界，现有开关不能替代这些机制 |
| `PT_DSH_UID`、`PT_DSH_GID` | 当前 POSIX 条件降权配置；未配置不代表已隔离，Windows 不支持此 spawn 身份机制 |
| `PT_HEARTBEAT_ENABLED`、`PT_HEARTBEAT_INTERVAL_MS` | 当前付费模型保活开关与间隔；默认关闭。需明确用户授权、BYOK 归属、预算与用量计量后决定是否启用，不能全站无条件打开 |
| `PT_MOCK_DSH`、`PT_CHAT_DRYRUN` | 测试开关；发布检查必须确认关闭，mock 通过不能算真实 Agent 验收 |

目标：交付完整配置表，逐项列必填条件、默认值、保密等级、重启要求和验证方式；新增 Google、队列、解析器等配置在实现后按实际命名补齐。配置缺失应 fail-closed 或明确降级，不能自动回落管理员 Key／演示租户。

### 2.3 BYOK 与 Google 身份

**当前 BYOK**：每用户绑定自己的 PT Key；保存校验、AES-256-GCM 加密与解密使用现有机制。`shell/keys.cjs` 在 Windows 使用 DPAPI CurrentUser，在非 Windows 使用受 0600 权限保护的主密钥文件；不能声称所有平台都使用 DPAPI。进程已具备环境变量白名单，但这不等于完整 OS 沙箱。

**目标**：Google OAuth/OIDC 是一期唯一登录方式。当前基线仍含密码体系，不把决策写成已经上线。实现后说明准确回调 URI、授权凭据管理、身份绑定、首次建 workspace、登出、会话撤销及账号禁用；Google `sub` 是稳定身份标识，邮箱属性与验证状态单独处理，不靠未验证邮箱合并账号。测试账号清理须有明确名单与备份，不因为「都是测试用户」直接删库。

生产禁止共享管理员模型 Key。测试通过安全临时渠道注入有余额的测试 Key，测试后清理；报告只保留脱敏标识。主密钥、Google secret、连接串、Cookie、上传内容均不进入 Git、截图、CI 输出或任务日志。主密钥丢失无法靠重置应用密码恢复加密 Key。

## 3. 数据迁移与存储维护

当前真实 `shell/auth.cjs` 默认迁移目录是 `shell/db-migrations`，已到 010；`shell/storage/migrations` 仍为 001–006，旧 Storage README 的「唯一权威」描述已经过期。**目标：统一迁移权威来源及唯一执行入口，再补升级测试；不能直接删除两边文件或假设重名文件内容一致。**

每次发布记录源版本、目标版本、数据库类型、已应用迁移、预计锁表与停机时间，先在脱敏副本执行旧库升级、重跑幂等与失败恢复，再验证历史用户、会话、工具调用、NULL 用量、文件归属。新库安装通过不能替代旧库迁移通过。PGlite 与 PG 都要覆盖实际启用路径；PG 生产连接使用最小权限角色与适当 TLS，不沿用示例超级用户。

代码回滚前判断旧代码是否兼容新 schema。优先向前兼容的增量变更；不可逆迁移要单列停机和恢复方案。禁止直接在生产执行示例 `--reseed`、删库重建或覆盖主密钥。迁移失败应非零退出并阻断启动／发布，不以捕获后继续服务掩盖失败。

## 4. DSH、插件与 Skill 升级

### 4.1 无侵入边界

产品通过 Runtime Contract 与 Adapter，使用 DSH 公开 SDK／CLI／插件扩展接口；不修改 DSH 源码、`node_modules` 或 vendor 包内部内容，不维护隐式补丁，不复制 Agent 循环。仓库自有 `persistent-runner.mjs` 是扩展接线，可随公开 API 调整。DSH 接口不足时记录缺口、验证替代方案或请求上游支持，不能悄悄 fork 内核。

Adapter 限制影响范围，但不能承诺升级只改一个文件；SDK、runner、配置、事件、工具和测试都可能需要适配。外部服务 HTTP 契约与 DSH SDK 不混为一谈，不为模仿其他产品而新增未经验证的 ACP 实现。

### 4.2 固定版本与升级门禁

当前顶层 DSH 本地 tgz 是 `0.1.1-rc.2`，传递依赖主要仍来自 npm；顶层 vendor 不等于全依赖离线可安装。保持锁文件完整性和精确版本，不用 `latest`／自动漂移。候选升级只在独立分支与隔离 home/profile 验证。

```mermaid
flowchart LR
 A[记录旧版与候选依赖] --> B[接口及配置差异审查]
 B --> C[契约测试]
 C --> D[真实 DSH 冒烟]
 D --> E[受影响能力回归]
 E --> F[独立验收与预发布]
 F --> G[发布并保留旧版回滚]
```

| 门禁 | 必须取得的证据 |
|---|---|
| 依赖与配置 | 新旧完整 hash、Node/OS、DSH 实际版本与入口、锁文件、插件精确版本、profile/bundle/patch 差异 |
| Runtime 契约 | 当前所有契约断言通过；历史 26 项只是原基线，扩展契约后按新集合执行 |
| 真实冒烟 | 冷／热会话、多轮记忆、流式、真实工具／PM Skill、停止、closeSession、错误、崩溃恢复 |
| 受影响回归 | 并发、跨用户隔离、模型切换与实际模型、附件读取、产物关联、用量、取消和长媒体任务 |
| 预发布 | 新环境重建、真实 UI 路径、代理 SSE、Google 与 BYOK、数据迁移和回滚演练 |

现有验证入口（在目标版本根目录执行，真实测试需受控注入 `DSH_LIVE_PT_KEY`；该测试凭据名不是生产共享 Key 配置）：

```bash
node tests/regression/runtime-contract-test.mjs
node shell/runtime/dsh-live-contract-test.mjs
node shell/runtime/dsh-live-smoke-test.mjs
node scripts/run-regression.mjs
```

真实脚本历史默认入口可能来自特定机器；使用其实际支持的 `DSH_LIVE_ENTRY`／`DSH_LIVE_MODEL` 显式确认候选环境，测试报告记录解析版本。余额不足、外部服务不可用是「未完成／受阻」，不是通过。禁止仅换 mock 或旧版本跑绿后宣称升级成功。

### 4.3 Profile 与 Skill

生产 DSH 使用产品专用 home、租户 workspace，不挂开发者 `~/.dsh`；`cordis.yml` 可能由 DSH 重建，定制装配走支持的 patch/bundle 机制。任何插件变更同步保存脱敏的生产 profile 配置、依赖版本、加载顺序、适用 profile 与重建步骤，验证重复挂载、兼容性和真实使用路径。历史 `web` 侧边栏插件快照不证明产品预览能力，不能直接复制到 `run-persistent`。

PM 添加／更新／发布／回滚 Skill；员工仅使用已发布版本。发布前验证依赖、工具权限、租户同步、兼容性与真实场景；运行任务固定版本，禁止更新中混用。记录发布人、版本、时间、内容指纹及回滚影响。员工自助安装、跨成员共享工作区和业务定时流属于二期。

## 5. 备份、恢复与灾难演练

**当前核查未找到旧总文档提到的 `backup.cjs`、`restore.cjs`、`key-migrate.cjs`、`key-import.cjs` 可执行文件，不能引用其历史测试数作为当前仓库能力。目标：补齐经过演练的入口及文档后才能通过生产验收。**

备份清单包括身份与业务数据库、主密钥及加密方案元数据、租户上传与产物、workspace/必要会话资料、PM 已发布 Skill 版本、生产 profile 和应用配置清单。数据库备份不等于附件备份；只备加密 Key 不备主密钥无法恢复。密钥备份与普通数据分开加密、分权保管，恢复时验证权限。

PGlite 先停止写入并确认进程退出，再冷备完整数据目录，禁止在线复制数据库文件冒充一致性备份。PG 使用该环境支持的数据库备份机制并取得一致性与角色信息。两者都需记录备份时间、完整性校验、加密、留存与删除规则；RPO/RTO 在预发布演练中测量并经负责人确认，不能提前声称达标。

恢复到独立目录／库，禁止先覆盖唯一生产副本。检查数据库完整性、迁移版本、历史登录与对话、BYOK 解密、附件／产物授权与跨租户拒绝。Windows DPAPI CurrentUser 跨机或换服务身份不能直接复用原 blob，必须交付可验证的加密迁移方案。恢复任何关键校验失败应非零退出；不得返回假成功。完整演练包含丢失主机、旧代码／新库不兼容、恢复后不重复提交外部生成任务。

## 6. 可观测性与排障

目标：服务访问、身份授权、任务／工具、模型尝试、目录同步、解析、产物和安全审计可按可信 `tenantId/userId/conversationId/runId/callId/requestId` 关联；记录实际模型、耗时、状态、错误码及来源，不收集明文凭据或默认完整文件正文。Token 未提供为 NULL／「—」，费用区分上游账单、估算与未知，不把缺失记为 0。

| 现象 | 排查顺序与判定边界 |
|---|---|
| 登录失败 | 区分当前密码旧版与目标 Google；检查回调 URI、state/nonce、身份验证及 Cookie，不能打印 token |
| 对话无响应 | 查服务探活、实际 DSH 入口／版本、Key 状态、队列／session、首字时间、上游请求；HTTP 200 不代表任务成功 |
| 余额／权限错误 | 分开显示额度不足、凭据无效、429 临时限流和超时；不能归成「没数据」或自动改用管理员 Key |
| 停止后仍计费 | 区分前端停止、DSH 取消确认、外部任务是否可取消；不能承诺已退款或上游已停止 |
| 文件上传后答不上 | 查归属、真实格式、解析状态、OCR／转换依赖、引用来源与上下文截断；上传成功不等于可理解 |
| 生成文件不可见 | 查 run/call 归属、存储与授权、CSP、媒体域名／过期 URL；PDF/HTML 预览还要验证隔离和脚本限制 |
| 用量异常 | 检查实际执行模型、重试／AUTO 多调用、计量来源、NULL 汇总与单位；工具步骤不虚构单次 Token |
| 某租户看到别人数据 | 立即阻断受影响链路，保留脱敏审计；检查可信身份绑定与 RLS，不使用演示租户 fallback |

告警至少覆盖进程退出、数据库不可用、任务长期无进展、队列积压、解析失败、目录同步陈旧、磁盘／配额、异常授权和备份失败。阈值按实测确定；新增告警必须构造一次触发与恢复，证明检测机制有效。探活日志降噪，业务失败保留关联信息。

## 7. 发布、回滚与最终交付

发布顺序：**实现者自测 → 未参与实现的 Claude 整体验收 → 预发布／部署验证 → 全新 Claude Code 按既有及本次补充测试任务包完整测试 → 通过后交付。** 任一必要环节受阻就保留未完成状态。测试不得对未经授权的生产用户、账单和外部写操作执行破坏性场景；生产只做受控冒烟，破坏及恢复验证放隔离环境。

发布负责人记录精确构建、依赖、迁移、配置清单、备份编号、测试数据与环境、实测结果、已知限制、回滚触发条件及值班入口。Google、DSH、PT、解析器、媒体与浏览器路径分别给证据；单元／mock／静态测试不能替代真实验收。CI 全绿也不证明未配置的分支保护已生效，合并规则需独立确认。

回滚时先停止接收新任务并处理运行中任务，禁止盲目重试可能已扣费的外部提交。按 schema 兼容性选择回滚代码或恢复整套一致数据，保留失败版本证据；恢复后复核会话、Key 解密、文件权限与外部任务映射，再恢复流量。新旧 DSH 的 session 数据不默认兼容，必要时依据已验证机制重建并重放。

最终交付必须补齐：可复现发布包、实际配置表、唯一迁移入口、生产 profile 快照、备份／恢复脚本与演练记录、监控触发证据、完整测试报告、回滚记录、维护人和访问权限清单。用户手工输入的域名／证书／OAuth 凭据等若缺失，明确列为外部前置条件，不把模板交付写成上线完成。
