# WB 分析文档对北极星一期的借鉴审查

日期：2026-10-15。范围：`wb copy/` 的 README、四份专题文档与 replication-rules.json；对照此前已核实的北极星 main 快照 `62f5b46dc83a05f39b6f910ef778496b5b1495ca`。本报告为方案审查，不修改产品代码，不替代唯一总文档，不代表下述功能已实现。

## 判断

这些资料很有价值，最适合补强“任务能持续执行、结果能交付、上下文能管理、权限有边界”的产品机制。北极星已有共享 DSH 基座，不能沿用它面向从零复刻产品的顺序再写一套 Runner、工具执行器和 SessionStore。应把有用机制接到 DSH 与现有业务壳之间，尽量复用已有运行时和存储。

一期优先吸收：独立任务上下文、增量事件保存、可恢复执行、受能力约束的模型路由、按需记忆与技能、可预览下载的产物、执行预算与重复失败熔断。Cron 业务流保留二期；每天同步模型目录是一期后台维护任务，不需要先建设完整业务流系统。

## 证据边界

目录包含四份专题 Markdown、README 和一份 JSON；没有原始 codebuddy.js、运行时样本或文档插件源码。文档虽然声明“全部从产物还原”，本轮只能核查说明与伪代码的逻辑、内部一致性和对北极星的适用性，不能据此独立证明 WorkBuddy 当前真实实现与全部运行行为。

replication-rules.json 可解析。说明称 SAFE 白名单有 116 项，实际 JSON 为 108 项。这不否定整体设计，但表明常量、阈值与“完整清单”需要复核，不应直接导入生产策略。

## 一期最值得吸收的机制

| 机制／出处 | 员工得到的改善 | 北极星落点 | 采取方式 |
|---|---|---|---|
| RunState 与每次执行独立 scope：01 §1 | 多对话同时工作，结果不串 | tasks + runtime adapter；runner 的全局结果变量迁为 run/session 局部状态 | 保留 DSH 循环，不另造内核 |
| 增量事件保存、callId、恢复游标：01 §1.4／§3 | 刷新或中断后可查任务经过 | DSH 事件经业务壳适配为持久任务事件；前端可按游标重连 | 不逐字写数据库，可按语义事件／批量落盘；避免重复保存两份权威历史 |
| 模型无关元数据侧车：01 §3.2 | 模型、工具、报告、费用与产物可追踪 | runId／requestId／callId 关联 usage、report、artifact | 不靠回复文本反向解析元数据；不以保存隐藏推理作为目标 |
| 能力角色与关联模型：03 第一部分 | 用户无需手工选模型 | PT 模型目录＋AUTO 需求规划＋协议适配器 | 先满足输入输出能力，再考虑速度／成本；失败只能转到兼容模型 |
| 小型记忆入口＋相关记忆按需加载：03 §9–12 | 跨对话记住偏好，长对话不臃肿 | 现有 user_memory 扩展来源、范围、相关性和删除行为 | 数据库可继续作为事实源；不强制改为全文件存储 |
| 技能元数据发现、按需读取：03 §14–17 | 技能更多时仍能快速选中能力 | PM 管理技能目录，记录版本、来源、状态和依赖 | 复用 DSH 技能加载；补版本更新与已有 workspace 同步策略 |
| 内容→排版→导出＋阶段契约：04 第一部分 | 真正拿到可用文件，能预览、下载、继续修改 | attachments 与 artifacts | 按用户所需输出格式选择路径，简单 MD 不必经过 DOCX 管线 |
| 工具权限与执行隔离分离、会话授权缓存：02 | 日常操作少打断，越权动作确实被拦 | 统一工具执行入口、可信用户上下文、受限文件／命令执行 | 自动处理已授权的工作区操作；外部副作用与权限扩张按真实风险决定 |
| 轮数／时间／调用次数预算与熔断：01 §1、02 §5.5 | 不反复失败、不无限烧额度 | run budget、工具去重、重试策略与用户可见停止原因 | 阈值按北极星场景确定，不照搬 500 轮等常量 |
| 文件快照与分支指针：01 §3.4–3.5 | 修改有版本，分岔不必永久丢弃旧结果 | 产物版本及对话分支 | 先做用户可见产物版本；共享 workspace 回滚须验证文件未被其他任务修改 |

补充发现：当前快照的 initTenantWorkspace 仅在目标技能目录不存在时拷贝。已有 workspace 不会因此自动获得同名技能的新内容。既然一期由 PM 统一接入技能，应有可控版本发布、缓存失效与任务中途不热替换的机制；不能只改共享目录便宣称所有用户都已更新。

## 不能照搬的规则与需要修正的保证

### 1. 恢复游标不等于外部动作恰好执行一次

01 §1.4 声称“增量持久化＋游标去重＝已完成工具不会重复执行”，保证过强。例如 PT 已接受视频任务，但进程在保存 taskId 前崩溃，本地游标无法证明上游发生了什么。

北极星应结合提交前意图记录、稳定幂等键、供应商 taskId 与状态查询；上游不支持幂等／查询且结果未知时，明确标记需核查，不能自动重复提交。只读查询和带费用／外部写入的工具，恢复策略不同。

### 2. 最终回退主模型必须有能力条件

03 §3 将 vision 等变体最终回退到主模型，不适合直接成为北极星通用规则。主模型若不支持图像，就不能接管图片理解；纯文本模型更不能替代图片／视频生成。

保留“角色到具体模型”的抽象，回退限定在满足需求、接口已适配、用户有权限且预算允许的候选内；无候选就明确能力暂不可用。

### 3. WB 的 Auto 权限模式与北极星 AUTO 选模不是一回事

02 §5 的 Auto 是由分类器决定某次工具动作是否需要阻止／审批；03 第一部分才涉及模型调度。北极星默认 AUTO 是任务选模，不应因此给每次工具调用增加两轮安全模型请求。

一期先用明确的参数校验、权限、预算与实际隔离。分类器可辅助判断模糊风险，但不是权限来源，也不能代替文件／网络隔离。

### 4. 命令名白名单不是安全边界

JSON 的 SAFE 名单包括 python、node、curl、ssh、docker 等，可以表达任意代码、外传或高权限行为。02 §2.2 的“SAFE 后只检查豁免”与后续对复杂参数检查的说明，也不足以证明整个命令解析链安全。

不导入该名单作为自动放行依据。使用受控工具、完整参数语义、shell 语法分析、真实权限和沙箱；同意一个任务也不意味着放行任意命令。

### 5. 技能自己声明的字段不是鉴权依据

03 §18 使用 registry 命中或 agent_created=true 作为修改／删除资格；对北极星而言，可编辑 frontmatter 只能描述来源，不能授予权限。用户已决定一期由 PM 管理技能，不开放员工自助添加。

保留技能目录、版本和按需加载；创建／修改／删除权限由服务端可信记录决定。新技能也不能通过 allowed-tools、hooks 或正文自行扩大权限。

### 6. 记忆可以删除，不能越过租户或覆盖权限

“文件系统唯一事实源、append-only”属于目标产品的一种实现选择，不是北极星必须采用的规则。保留当前数据库可以减少分叉。

记忆需支持查看、纠正、删除、失效与来源标记；用户数据删除应覆盖索引与派生摘要。业务记忆不自动升级为系统指令，后台提取不能为此获得全局 BypassPermissions。

### 7. 文档不必永远导出 DOCX，也不应隐藏所有中间可用结果

04 的强制 S1→S2→S3 和“只预览最终 DOCX”服务于特定文档产品。北极星用户要求 MD、HTML、PDF 或数据表时，应直接交付对应产物。

保留阶段输入输出契约、模板、渲染验证和降级记录；可用的 Markdown 或 HTML 可先交付，不应因 DOCX 转换失败而丢弃正文。文档生成、文档读取问答和视觉／音视频理解仍是不同能力，该管线没有自动解决解析与检索问题。

### 8. 伪代码不等于可直接运行的实现

01 §3.3 的 writeLocks 示例把 prev.then(() => gate) 存入 Map，清理时却与 gate 本体比较，示例中的比较对象不一致，存在锁条目不清理的风险。即便这是摘录或简化造成的，也说明应先验证契约和行为，不能把“完整还原”当作测试通过。

## 北极星应保留的架构边界

| 层 | 职责 |
|---|---|
| DSH | Agent 循环、session 生命周期、流式、Agent 级取消与原生工具机制 |
| 北极星 runtime adapter | 把身份、workspace、任务与 DSH session 正确关联；消除共享状态 |
| 北极星任务层 | 持久任务、预算、重连、恢复、外部生成任务状态 |
| 模型层 | PT 能力目录、AUTO、协议适配与兼容回退 |
| 附件／产物层 | 文件理解、引用、版本、预览、下载 |
| 工具／用量层 | 统一授权执行与请求／步骤／费用关联 |

DSH 原始 session 事件和业务任务事件的职责应明确；UI 消息是展示投影，不能另起一套会独立执行工具的会话内核。JSONL 与 PostgreSQL 可以各有用途，但同一事实不能在两处独立编辑后都声称权威。

## 面向一期的交付顺序

### 第一批：任务可靠，给现有能力补闭环

多 session 独立状态、按对话并行、任务事件持久化、停止收敛、日志／用量关联、多结果保存与报告详情对模型可见。对应此前 C／D／J／K 包，复用原估算，不另加一轮“WB 改造费”。

验收：A 生成视频时 B 能工作；刷新可查 A；停止 A 不影响 B；失败也保留已完成工具；用户能追问报告的真实问题。

### 第二批：资料进入，产物交付

文件解析与引用、确定性表格计算、文档／图片／视频结果的多产物预览和下载。对应此前 G／H／I。将文档管线中的模板和阶段验证作为实现参考，不先做八类专家 Agent 与复杂编排。

验收：员工上传约定格式的真实资料，得到带出处的分析和可再次下载的结果；格式转换失败仍保留已有可用产物。

### 第三批：让能力可选、上下文可控

PT 每日目录、任务能力路由、兼容回退、按需记忆与技能版本管理。对应此前 E／F／L 和技能治理工作，和前两批按依赖交错推进。

验收：默认 AUTO 正确区分看图／生图／生视频；未知能力不伪装支持；新对话记住用户确认的稳定偏好，删除后不再召回。

二期继续保留：周期业务流、跨用户协作、复杂可视化编排。文件系统级完整回滚、多角色专家流水线、自动创建技能，不作为一期基础能力完成的先决条件。

## 可交给 Claude 的补充评审要点

1. 复用 DSH，禁止因阅读复刻包而另造 Runner／SessionStore。
2. 将 run/session 局部状态与增量任务事件纳入并发改造，统一 requestId／callId／artifactId。
3. 模型选优与权限 Auto 分开；回退不能跨越能力边界。
4. 产物交付采用用户目标格式＋预览／下载＋验证，不强制 DOCX。
5. 记忆按需、有来源、可删除；技能由 PM 统一版本化管理，不开放自我授权。
6. 增量保存不承诺外部动作恰好一次；付费任务恢复必须考虑上游未知状态。
7. 不直接导入 replication-rules.json 的命令白名单、阈值和权限枚举。

结论：这些资料能帮助完善既定一期方案，尤其能把“功能存在”推进到“任务可靠、结果可交付”。它不是当前项目必须整体复制的新架构，也不足以证明原产品全部运行行为。
