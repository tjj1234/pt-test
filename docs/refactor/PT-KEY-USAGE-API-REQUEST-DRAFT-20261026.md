# 给 PowerTokens 的按 Key 用量接口需求草案

**状态：本 Agent 未发送；2026-10-27 收到用户补充的六项 PT 技术接口需求。** 下列路径是建议接口，尚未确认已开放。北极星 F3 自行逐次记录调用并按官方价格版本估算，不等待 PT 接口；未来接口用于状态预检与官方账单核对。

希望提供以当前 API Key 鉴权、仅返回该 Key 自身数据的只读用量接口，支持 UTC 时间范围与稳定分页游标。每条记录建议包含供应商请求/任务 ID、提交和完成时间、请求模型与实际计费模型、端点/任务类型、计费参数（如输入/输出 token、缓存 token、张数、分辨率、输入/输出时长）、计费单位、币种、单价版本、实际扣费、最终状态及退款/调整记录。异步媒体任务和断连后未知结果应可按任务 ID 查询；记录需要稳定唯一 ID 以便去重和核对。

需要明确：价格变更的生效时间、失败/取消/部分完成的计费规则、账单数据延迟、分页一致性、保留期及限流。接口可只支持本 Key，不需要跨账户或管理员账单权限。返回字段不能包含明文 Key。

## 用户补充的六项需求与实现边界

| 项 | 建议路径 | 北极星接入原则 |
|---|---|---|
| 1 资产库/协议状态 | `GET /v1/asset/agreement/status` | 只读，按当前 Key 查询 asset_library_enabled/agreement_accepted/accepted_at/account_id；account_id 与 userid 的关系待 PT 定义。接口未开放前不伪造状态、不代签，也不把本地布尔标记当服务端证明 |
| 2 逐次消费记录 | `GET /v1/logs/query` 或复用已有记录 | 沿用 PT consume/request/task/model/status/usage/billing 结构，结果自动限于鉴权 Key；按记录 ID 去重，用 request_id/task_id 精确关联本地 Run，不用模型+时间模糊对账 |
| 3 按 Key 账期汇总 | `GET /v1/billing/usage` | 与逐次明细可共用底层数据或同一接口的汇总视图；缓存标记、as_of、统计范围及账单修订必须明确，不能把本地估算与官方实扣混在一个金额里 |
| 4 按 Key 可用额度 | `GET /v1/billing/balance` | 用户明确额度单位为 credits：有限额 Key 查询该 Key 剩余额度，无限额 Key 查询账户可用余额；仅换算汇率/生效版本待确认。建议加 balance_scope=key_limit/account，避免语义混淆；预检值不保证并发调用后仍可预扣 |
| **5 生成错误码细分** | **PT 无法实现，不作为依赖** | 同码同文案的素材未入库/内容违规保持模糊拒绝，不靠关键词拆原因，不自动上传/改参数/重提POST试错。远端明确失败与网络提交结果未知仍分别记录 |
| 6 跨模型异步任务 | `GET /v1/tasks/{task_id}`、`DELETE /v1/tasks/{task_id}`；统一提交待评估 | 若未来有接口再接统一状态适配；当前复用引擎既有提交/查询，不重复造模型轮询。DELETE 是否真实取消、哪些模型支持、取消后计费与最终状态须由 PT 定义；本地停止不等于远端取消 |

请求筛选建议消除稿件中的歧义：request_id、task_id、完整 start_time/end_time 范围三组**恰选一组**，request_id 不能同时被标为全局必填；范围查询需 limit/cursor、稳定排序、UTC 与半开区间、最大跨度、数据延迟/保留期。是否存在“请求失败但无消费记录”也需说明，缺记录不能直接判免费。

官方返回费用保留 credits 原值；`currency` 不应误写成 USD。汇率若开放，需单位、版本/生效时间与舍入规则；不能用样例中的 quota_per_unit 或网页当前价格推断历史换算。账单汇总还应说明成功/失败/取消/退款与调整行的归集方式。

**本期估算口径已获用户接受**：已知请求模型、实际响应 token 与调用前绑定的官方价格，即可按请求模型估算；上游身份未提供时继续 null/unknown，并显式保存 `costBasis=requested_model`。若上游明确报告不同模型，仍保留不一致状态待核对。以后 PT API 可用再附加官方使用量/扣费证据，保留原估算及来源供差异核对，不静默改写历史估算。
