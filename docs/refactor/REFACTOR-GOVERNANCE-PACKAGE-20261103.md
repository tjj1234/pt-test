### 3.1 自动目录同步：本轮已确认需求
同步是平台维护任务，不是26包的用户业务自动化，不等待26上线。建议默认每天一次（UTC定点，具体时刻/抖动/超时由负责人配置），支持配置周期；重启漏跑只合并补最近一次，不积压无限补跑。复用现有持久调度/租约，按provider/base/tenant/KeyRef/KeyRevision控制单活和有界并发；离线Key、撤销Key不继续查目录，不将凭据写入任务参数日志。

| 阶段 | 自动行为与发布条件 | 失败/异常边界 |
|---|---|---|
| S1 获取 | 用当前Key请求已核实的PT `/v1/models`，抓完全部分页，记录接口/能力版本和有效范围 | 401/403、429/5xx、断网、超时、分页不全、解析错均为同步失败；不能将失败/缺页当空目录批量删除。只读同步可有界退避，不触发任何推理/生成调用 |
| S2 校验与比较 | 对完整、可信scope的快照比对新增/变更/消失；只有PT明确有效的完整空目录才发布空快照 | Key过滤结果不用于删除全平台目录；PT未确认完整性/空快照含义时保留last-good并标stale，告警但不进入人工逐模型审批流程 |
| S3 原子发布 | 无需人工审核发布新目录镜像revision；新增模型自动进入按task/Key过滤的候选构建，消失/明确下架项自动移出当前镜像和对应候选 | 历史模型/Run/账单保留tombstone及证据，不物理抹除；发布失败保留上一版，镜像与候选不可一半新一半旧 |
| S4 当前Key预筛 | `allowed=false`、明确停用/模式不支持、协议未满足等直接排除，不做真实调用；`allowed=true`还须满足可信任务能力、参数、DSH/provider配置和原执行门禁 | 字段缺失/过期/unknown标未知并排除新候选；不从名称/目录存在推权限，不伪造verified。不自动扩到原本关闭的媒体AUTO/未支持任务 |
| S5 在途与缓存 | 新选择用新revision，已选但未提交者提交前重验；Key变更使旧资格缓存失效，快照发布使对应候选缓存失效 | 已提交的Run保留原模型/配置/attempt快照，不因下架切换重提；查询旧任务不依赖模型仍在当前目录，未知结果继续核对 |
| S6 留痕 | 每次成功/失败/无变化均记录syncId、计划/实际时间、触发源、匿名Key scope/revision、页数/数量、前后SHA/revision、增删改原因、执行者/lease及错误类别 | 不记录Key/原始用户正文；记录no-op/失败和自动变更理由，能还原某次选择使用的目录/资格版本；同快照重复调度不重复发布 |

完整性/当前Key字段尚未由PT提供或确认时，自动读取现有目录可继续，缺事实的资格/删除操作保守受限；不替PT编造事实，也不以人工逐模型审批代替本轮已确认的自动化目标。范围缩减的部分保持未完成。
