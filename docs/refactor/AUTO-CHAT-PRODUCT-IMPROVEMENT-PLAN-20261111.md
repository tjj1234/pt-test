# 单聊天框 AUTO 改进方案

状态：方案已补充；锁定DSH原生小验证8组通过；产品尚未实现或部署。基线：已上线 R34，运行源码1586f76。本文以用户2026-11-11的新澄清为准：用户只描述目标；系统理解需求、选择模型和工具、执行步骤并交付结果。用户不负责选择技术模式或排查执行错误。

## 1. 纠正目标与当前差距

当前AUTO是调用前资格选模，不是完整任务规划。联网、账单、文件、澄清和分析的互斥复选框，把内部执行策略变成用户操作负担。普通对话128 token和压缩摘要128 token属于试运行配置，不满足正常聊天。已上线的组件和正式发布事实保留；完整AUTO聊天仍是未交付项。

目标入口：一个聊天框、附件、发送、停止。用户可选的模型和偏好放入高级设置；默认无需操作。系统按需显示简短进度、必要问题、结果、引用及下载文件。

## 2. 用户结果契约

| 结果类型 | 必须交付 |
|---|---|
| 普通问题 | 直接流式回答。简单任务不为规划而多起一个模型请求 |
| 可执行复合任务 | 自动安排依赖并执行；返回真实结果和文件 |
| 信息缺失 | 在聊天内只问影响执行的必要问题；保留已有进度 |
| 授权缺失 | 在聊天内提供一次必要授权入口；不要求用户研究模型和工具 |
| 部分不支持 | 完成有价值的支持部分，清楚指出未完成部分；任务不可分时明确暂不支持 |
| 临时执行错误 | 系统自动恢复、换合格模型或使用可用路径，不把堆栈、错误码和模型选择交给用户 |
| 仍不能完成 | 返回已完成内容、具体缺口及清晰状态；不谎称完成、不生成虚假文件链接 |

“暂不支持”只用于当前产品能力确实不足。429、偶发超时、缺价格快照、某一个模型不可用，不直接归类为产品不支持。

## 3. 自动执行流程

1. 从已登录用户及附件读取可信身份和输入，取得同Key模型目录、接口能力与宿主工具目录。
2. 对简单文本请求使用低成本合格模型直接回答。第一轮可同时承担理解任务和回答，不强制浪费规划调用。
3. 对复合请求调用低成本规划模型。输出受控计划：目标、必要输入、步骤、依赖、模型能力要求、工具、交付物和完成条件。
4. 宿主验证计划只使用已接入能力、owned输入和允许动作。规划模型不得创造工具或从文字推导新的系统权限。
5. DSH按计划执行。根据每步要求选择当前Key可用的合格模型。依赖步骤顺序执行；独立只读步骤可受控并行。
6. 工具结果回到DSH原生上下文。对可恢复错误执行有界重试或选择其他合格模型。
7. 检查完成条件。文件需要真实存在且可下载；联网结论需要真实来源；数值结论需要对应输入或计算证据。
8. 完成交付。未满足时在剩余额度内补充；达上限则保留部分结果并说明缺口。

不强制每个任务都调用多个模型。能由低成本模型完成，就不升级。确需视觉、代码分析或长文本能力时，系统自动选择对应模型。低成本选择优先使用审核价格；价格未知时使用后台配置的合格候选顺序，标明成本未知，不要求用户选择，也不宣称已确认最便宜。

## 4. DSH复用与最小宿主补充

| 环节 | 优先复用 | 必要修改 |
|---|---|---|
| 模型执行 | DSH Agent、Session、LLM及installModelSelection | 将当前整Run固定模型改为每步冻结模型和资格；切换前检查新步骤输入兼容 |
| 工具循环 | DSH tools注册/执行/限制及原生结果继续 | 每步从宿主验证的计划派生工具范围；替代浏览器allowX字段的授权作用 |
| 联网/提问/Skill | 既有ctx.web、userQuestions、skills provider | 按需求自动启用；默认用户无需勾选 |
| 只读分析 | 既有fs/subprocess、Landlock/seccomp与资源限制 | 一次授权及独立安全门禁通过后，实行有界系统预授权；保留Run/参数/策略证据 |
| 审批 | DSH approval及持久审批记录 | 区分system_policy与user_confirmation；系统授权不得伪造为用户点击批准 |
| 文档产物 | 既有document_export与writer | 允许在同Run计划中接续联网/分析输出 |
| 多步依赖 | 先验证锁定DSH原生轮次、Session、取消及现有工作流能力 | 仅补计划/步骤状态和可信调度接缝；不另造模型与工具执行引擎 |
| 任务恢复 | 既有Run/事件/租约/取消/预留 | 步骤、尝试、产物和恢复决定持久化；已成功步骤不重复执行 |
| 用量 | 既有usage/price/intents | 规划、执行、压缩、重试和外部生成分别记账，并给出任务汇总 |

已确认当前Runner模型选择对象可按轮次更新；当前server模型意图校验却绑定整Run的selectedModel，必须一起调整。不能只隐藏复选框或在前端全部设置true。

规划/步骤持久化优先扩展既有任务记录。若锁定DSH原生能力满足要求则直接复用。缺少持久状态时只增加最小宿主记录，不要求开放子代理、任意Shell或文件编辑器。

## 5. 用户授权语义

| 操作 | 自动执行原则 |
|---|---|
| 对话、可信联网、读取用户所提供资料、生成新报告文件 | 设置页有效授权范围内，用户目标包含这些操作时，计划验证后自动执行 |
| 既有隔离只读Python | 设置页一次明确授权且独立安全门禁通过后，策略内自动执行；不再逐段要求用户看代码 |
| 官方账单 | 已绑定令牌时按请求读取；缺少令牌时聊天内引导一次授权 |
| 当前已支持的付费图片/视频生成 | 用户明确要求生成即进入对应授权流程；记录次数/任务和真实消耗，不反复要求选择模型 |
| 不属于已开放范围的动作 | 明确暂不支持；不能用AUTO绕过原来关闭的任意终端、任意文件写入或外部系统操作 |
| 将来接入的外部发送、支付、删除、覆盖或发布 | 需要具体动作确认；不属于本轮新增功能 |

只读系统预授权属于行为变更，须独立验证策略范围、不能写/联网/派生进程、取消及审计字段。审批数据库与UI不得把system_policy展示为用户明确同意。

## 6. 费用与每模型重试规则

按用户原话解释：每个模型在同一用户任务内最多重试3次，首次调用不叫重试。因此针对失败请求，首次1次加重试最多3次。正常后续步骤、继续生成与失败重试分别计数，不混为一项。

- 不采用“整个任务最多调用3次”的旧建议。
- 模型Key具备权限、接口支持且上游未报告余额/额度不足时，允许正常付费调用。无法独立查询余额不等于余额为零。
- 计次模式下，缺少本地单价不单独阻断；新增金额上限后的默认审核预算模式以第12节为准，不承诺在价格未知时仍保证金额不超。官方账单关联缺失与请求是否可执行分开处理。
- 重试计数按taskId+provider+model持久化，换步骤、刷新或进程恢复不能清零；只有真实重试才累计。
- 选择其他合格模型后继续执行。不是让用户手工换模型，也不假设新模型有旧模型的视觉/工具能力。
- 候选集有边界；保留后台任务总调用/总时长兜底，不能不断换模型绕过停止条件。建议初始总模型请求24次、活动执行10分钟；这是方案默认，需随验收确认，不替代每模型3次重试。
- 规划及上下文压缩也记录真实模型调用。外部图片/视频生成另外记录计费操作，不能藏在模型次数后面。
- 不把自动恢复称为零费用。已发生的供应商消耗照实记录，未知不补零。

| 错误/情况 | 自动处理 |
|---|---|
| 模型429、5xx、可恢复文本超时 | 尊重Retry-After；退避重试，计入该模型3次额度；仍失败则换合格候选 |
| 模型不在Key权限中/接口不支持 | 刷新目录或修正已知参数；不反复重试相同确定失败，选择其他候选 |
| Key失效、余额或账户额度明确不足 | 停止本次付费执行；聊天内明确说明需要账户授权/充值，不伪称任务不支持 |
| 文本已产生部分输出后断开 | 保留文字；可在额度内续接或重新请求，实际发生的消耗照实记录 |
| 图片/视频创建返回未知 | 使用相同幂等键或查单恢复；不当作新任务创建。查询与创建重试分账 |
| 供应商无幂等也无可核查任务号 | 系统说明本次结果未能确认；不让用户排查技术问题，也不盲目重复创建付费产物 |
| 本地估算价格未知 | 审核预算模式自动换有可信上界的候选；只有设置页另行授权的计次模式可继续未知价；见第12节 |

旧表述“费用未知不自动换模型重提”原意是防止重复提交已经可能扣费的同一个操作。它不应被扩大成“必须拿到零费用账单证据才能继续聊天”。本轮要改成按请求类型恢复，普通文本和不可逆外部生成分别处理。

## 7. 取消过小的输出限制

| 内容 | 建议默认上限 | 处理 |
|---|---:|---|
| 普通回答 | 8192输出token | 按任务需要输出，不强迫写满 |
| 长报告/结构化文档内容 | 16384输出token | 按模型真实能力收敛；更大文档可分段写入受控产物 |
| 规划结构化结果 | 1024输出token | 简单问题直接回答时使用正常回答额度，不以规划上限截断 |
| 上下文摘要 | 2048输出token起，按内容调整 | 复用原生compaction，保留目标、约束、已完成步骤与产物引用 |

实际输出上限不得超过模型限制及剩余上下文。模型最大输出低于建议值时选可满足需求的模型或分段。finish_reason=length不能冒充完整交付：系统需要续写、分段或明确说明未完成。后台记录原因，不把调参任务交给用户。

## 8. 界面改进

主界面保留聊天框、附件、发送、停止。保留设置页一次授权及撤销，见第13节；未授权能力不隐式打开。移除五个能力复选框的逐任务必选职责；模型选择移入高级设置。AUTO为默认。

显示简短执行状态，例如“正在查找资料”“正在核对数据”“正在生成报告”。默认不显示技术调试清单、堆栈或工具权限选择。详细步骤、实际模型、重试、用量仍可在任务详情查看。

新任务失败时不清空已有结果。刷新或重开恢复真实进度与结果。用户点击停止后，终止仍在执行的可取消步骤；不触发新模型或生成请求。

## 9. 验收场景

以下验收均从默认聊天框开始，不切换能力模式，不选择模型。API/模块测试不代替独立点击、输入、上传、下载、刷新和重开。

| 场景 | 通过条件 |
|---|---|
| 一般问答，要求详细解释 | 回答自然完整；不被128 token截断；简单任务不额外强制规划调用 |
| 最近消息→比较分析→中文Word | 自动联网、整理来源、生成真实可下载Word；一个用户任务内完成 |
| 上传CSV→计算→Excel及说明 | 自动选择确定性计算或隔离分析；无需用户勾选；结果可复算、文件可打开 |
| 扫描PDF→摘要→PDF报告 | 自动OCR、页码引用、报告生成；解析限额和错误诚实显示 |
| 音视频→内容总结 | 自动本地处理与合格视觉/文本模型；无需用户判断输入模态 |
| 已授权官方余额问题 | 自动调用账单只读接口；币种与估算分开 |
| 缺少必要输入 | 仅问关键问题，答复后同任务继续；不要求用户选技术方案 |
| 请求当前不支持的能力 | 明确暂不支持，不生成假工具、假来源或假产物 |
| 首选模型连续临时失败 | 自动执行最多3次重试，再换合格候选；持久计数可核验 |
| 403/不支持模型参数 | 不浪费3次相同请求；自动选择可执行路径 |
| 缺少价格快照 | 自动选有价格上界的候选；另行授权的计次模式可执行且标unknown；不伪称金额硬帽有效 |
| 长输出达到模型上限 | 自动续接/分段或标未完成，不谎称已完成 |
| 文本断流 | 保留已收内容；恢复过程不跨会话或覆盖历史 |
| 媒体创建响应丢失 | 幂等/查单恢复；不生成多个重复付费任务 |
| 刷新、重开、进程恢复 | 已完成步骤不重做；已发生重试不清零 |
| 用户停止 | 后续步骤不再派发，已交付内容保留 |
| 跨账号及提示注入 | 不能访问别人的输入/账单/文件，不能借计划获取任意系统权限 |
| 费用审计 | 规划、执行、辅助请求、重试和外部生成均能区分；未知字段不捏造 |

## 10. 实施顺序与发布要求

| 顺序 | 交付内容 | 放行条件 |
|---|---|---|
| 1 | 冻结计划契约、每模型重试计数、阶段选模、授权语义与输出预算 | 一次完整生命周期矩阵，避免靠零散反例反复返修 |
| 2 | DSH原生多步执行与动态工具范围；接通现有01–08组件 | 真SDK和实际存储证明整条复合任务可执行；无另造Agent循环 |
| 3 | 系统只读预授权、恢复策略和任务交付校验 | 自动性与权限边界同时通过，数据库审计不伪造用户批准 |
| 4 | 默认单聊天框界面、状态与结果恢复 | 真浏览器无需模式选择完成场景 |
| 5 | 整包回归、独立QA及同版本生产核验 | 绑定commit/归档/配置；确认真实模型调用与重试计数、结果和账单事实 |

开发和验证可分步，不能把“按钮隐藏”或“token加大”单独称作本目标完成。原R34上线事实与本方案待实现状态分开登记。是否完成，以用户从一个聊天框得到真实结果为标准。

## 11. 补充审查结论与小验证（2026-11-11）

本节及后续章节覆盖前文未确定的预算、授权、持久状态和恢复细节。状态仍为方案；仅增加隔离探针与文档，不修改产品运行代码，不部署，不发起真实模型/媒体调用。

**结论：原生复用路径可行；不需要另造Agent循环。不能把探针通过等同整套AUTO或真实PT调用通过。建议按本补充冻结契约后实施；本轮未整体开工。**

| 实测对象 | 结果及证据边界 |
|---|---|
| 版本 | 锁定的dsh-agent / agent-loop / llm / tools均为0.1.1-rc.2；回执绑定锁文件及探针SHA |
| 同轮多步 | 同一个Agent、同一个Session、同一个turn内，planner-a→worker-b→writer-c；原生循环自行执行两个工具并继续模型请求 |
| 数据传递 | 后一步实际模型请求包含前一步tool/result中的内容及SHA；未由测试代码手动调用下一模型 |
| 动态选模 | 修改原生installModelSelection共享引用，下一步骤实际adapter收到新model |
| 原生工具范围 | 全局注册工具可由原生tools.restrict逐步切换prepare→render→空；撤销的工具body未执行 |
| Agent局部工具边界 | 原生restrict不覆盖局部注册定义。负例实测该定义仍可见；加原生tools/execute宿主门禁后body被拒绝。不能只依赖工具隐藏 |
| 两Session范围 | 两个原生Agent的模型和消息范围互不串用；这不是PostgreSQL租户隔离验收 |
| 取消 | 活跃工具收到取消信号；取消后没有下游模型请求 |
| maxCost | 现有budget.cjs能预留并阻止并发超额，支持有证据结算；未知估算/未知结算会RUN_COST_UNKNOWN |
| 模型端 | 确定性LlmAdapter，不是真实PT模型。网络出口被探针拒绝，无真实Key |

[探针源码](../../tests/probes/auto-chat-native-feasibility-20261111.mjs)；[八组实测回执](evidence/AUTO-CHAT-DSH-FEASIBILITY-20261111.json)。另对已有锁定CLI/真实pi-ai适配器的本机回环模型切换回归实测1/1通过，见[CLI回执](evidence/AUTO-CHAT-DSH-CLI-MODEL-SWITCH-20261111.txt)。它验证实际发送模型ID，但不是同一turn的完整产品调度。

当前R34宿主仍有整Run selectedModel校验、互斥模式、固定预算和未知费用保护。原生能力可复用，不表示这些宿主接缝无需修改。实施时保留SDK原生模型/工具/取消流程，只补计划和权限接线。

## 12. 金额、生成次数与预留规则

### 12.1 建议默认值

以下金额是产品预算建议，不是PT报价。金额必须由设置页明确授权，冻结进任务后不可被模型提高。租户管理员上限、用户授权上限、任务所需上限取交集。

| 项目 | 建议初值 | 计数口径 |
|---|---|---|
| 普通文本/资料/报告任务 | maxCost={amount:1,currency:USD} | 规划、执行、重试、压缩都共用一份任务预算 |
| 用户已另行授权的含图片/视频任务 | maxCost={amount:5,currency:USD} | 全任务合计5，不是每步5，也不是1+5；不得在任务中静默从1涨到5 |
| 图片 | 最多2个生成操作/任务；每操作n=1 | 所有模型共用。初次创建、失败后的新建和模型改投都占用；最多生成2张，不允许批量n绕过 |
| 视频 | 最多1个生成操作/任务 | 参数只取审核适配器允许的时长/分辨率；不在失败或未知后另建一条 |
| 同一媒体操作的幂等重放 | 仅PT确认幂等契约后启用，重试最多3次 | 同一个operation_key和参数哈希；不是新的生成名额；每个物理POST均审计 |
| 文本模型失败重试 | 每任务、每provider/model最多3次 | 首次另计；跨步骤/刷新/进程恢复不清零 |
| 模型总请求兜底 | 24次/任务 | 含规划、续写、压缩及失败重试。媒体创建另受上述次数和同一金额账本限制 |
| 活动执行时长 | 10分钟/任务 | 等用户补充信息可暂停活动计时，但设置总过期；外部视频受理后超时仍要查单恢复 |

次数上限与金额上限同时生效，先到者停止新付费步骤。用户未授权媒体时，不因一句模糊请求自动创建媒体。设置页一次授权可允许明确媒体目标自动执行，不需每步重新选择模型。

### 12.2 现有maxCost必须正确接线

现有budget.cjs是进程内预算，不是跨进程账本。当前Runner在构造请求后就调用admission.settle()且没有actualCost；若直接加maxCost，第一笔结算后将变成unknown并阻断后续。本探针已验证该行为，不能把配置字段存在当作已完成接线。

实施顺序：先在数据库同任务账本原子预留，经实际模型/媒体执行后结算，再允许下一付费步骤。持久账本为权威；budget.cjs作为现有准入守卫复用。恢复时从未结算预留重建，而非重开一个空预算。

1. 请求前按可信输入计数上界、输出上限、模型/参数和审核单价计算最大预留。reasoning、缓存、图片尺寸、视频时长等收费维度必须计入；不能只估答案文字。
2. 用行锁及整数最小单位执行spent+reserved+next<=max。USD账本建议纳美元整数或等效定点Decimal，尺度随币种冻结，预留向上取整；budget.cjs的浮点守卫不替代数据库整数账本。无足够额度则不派发。并发模型、重试和媒体使用同一行锁/账本。
3. retry计数事件不重复预留模型金额；实际重试请求才预留一次。只有受信本地免费操作可记0，未知报价不能记0。请求结束且用量/计价证据足够时结算。保存price_snapshot_id、币种、usage证据、计算公式版本及provider记录。释放实际未用预留。
4. 无用量、断流、超时、进程退出或受理未知时，不释放为零，不伪造actualCost。保留预留或冻结付费分支，执行查询恢复；免费本地整理与已有结果展示仍可继续。
5. 本地算得的USD必须标reviewed_estimate；PT官方credits标provider_debit。不能把估算塞入actualCost后再声称已核对官方扣费。

### 12.3 金额硬帽与未知价格的冲突

新增金额限制后，“任何未知价格都继续调用”和“严格保证金额不超”不能同时成立。推荐默认使用**审核价格预算模式**：自动选择有可审计价格及可证明上界的候选；缺该模型价格时自动换候选，而不是让用户查价格。

若所有候选都没有可证明上界，不能保证任务金额上限。设置页可以单独提供“仅限制次数，允许未知价格”授权；默认不勾选，租户可禁止。该模式必须明确maxCost未生效，不能一边继续未知价调用，一边显示金额硬帽有效。这一规则覆盖前文“未知价一律不阻断”的旧表述。

现有两个审核模型价格为USD，而且cacheWrite单价为null。本轮不能宣告它们已具备完整收费上界；硬额路径需要补齐该维度或取得可验证的协议排除/上界，不能假定缓存写入永不发生。官方账单可能是credits。现阶段maxCost只能约束同币种的审核估算账本；不能宣传为PT钱包官方实扣绝对上限。要承诺官方实扣硬帽，需要PT提供同币种的完整报价上界/受理限额与可关联扣费证据。未满足前，界面明确“审核估算预算上限”。不推算USD/credits汇率。

硬帽路径不以字符数随意猜Token、不将未知缓存写入价格设0，不把工具开销重复计成模型消耗。未知维度但实际用量为0时可按明确规则不收费；有未知用量时必须保守处理。

验收：并发临界额度、两个worker抢最后名额、崩溃后恢复、重复结算、预留未释放、输入/输出/思考Token遗漏、币种不符、过期价格、媒体重建、改模型后总额、撤销并发、账单迟到，以及估算超上界后的冻结告警。budget.cjs原有unknown默认测试保持通过，不靠删除失败门禁通过。

保留“设置页一次授权/可撤销”。聊天框不要求每次勾选能力，但自动执行必须落在有效授权范围内。以下为能力授权，不是替用户批准未来任意动作。

新增授权记录建议名agent_user_capability_grants：tenant_id、user_id、capability、grant_version、policy_revision、limits_json、granted_at、revoked_at、revision。个人设置和授权表只存元数据；真实模型Key沿用既有密钥存储，账单令牌沿用既有独立加密表。密钥不放进计划、步骤、事件或模型消息。

撤销流程：在事务中撤销并递增grant_version，失效尚未消费的执行许可；标记受影响活动Run和广播取消。每次新dispatch前在数据库核对授权版本、成员资格及租户策略，不能只信缓存。所有实例下一步均不得取得新许可。

在途模型/本地进程尽力取消并join。已提交外部媒体不承诺撤销成功或退款；保存operation/task状态并在合法凭据仍可使用时只读查单。删除Key/令牌后不得私藏副本继续查询；无法恢复的外部结果保持未知。安全说明：“撤销阻止新的执行许可，已受理调用可能继续计费”，不声称撤销能撤回网络请求。

撤销与dispatch共用事务序列化点。撤销前已消费许可的请求归为在途；撤销后不再创建许可。网络发送和数据库事务不能宣称天然原子。批准/撤销/派发竞态须有确定测试点。

变更额度或开启新能力不扩大已经冻结的任务计划。用户收紧/撤销则立即约束原任务。重新授权后不得自动重放原任务；新任务或明确继续操作才建立新计划版本。

隔离方式：HTTP从认证上下文取tenant/user；所有repository方法显式要求二者，先验证owned Run，再执行带二者条件的SQL。复合FK覆盖父子tenant/user/run，防止A租户步骤绑定B租户计划。恢复worker通过已认领owned Run构造身份，不从模型参数取身份。

预算和重试计数均在锁与有效lease/revision下原子更新。授权、输入、输出、模型、币种和实际请求都绑定同一scope；换Key必须形成新credential_scope，不允许拿旧Key资格给新Key派发。

隔离验收至少覆盖：A/B不同租户；同租户两用户；伪造plan/step/attempt/ref；相同step_id；读取/取消/恢复越权；SSE/产物引用越权；复合FK写入失败；运行角色直连RLS；空上下文；连接池交替复用及异常回滚；并发worker；重启后不串账；更换Key；成员移除与授权撤销；重试计数无法跨scope清零。结果分别记录，不以原生双Agent测试代替。

## 15. 规划模型、格式与冻结

### 15.1 明确模型选择

建议首选glm-4.7，备用deepseek-v4-pro。理由：两者在当前DSH配置中，已有审核USD价格；不需要引入新provider/密钥。不是声称它们在所有账号可用，也不是声称绝对最便宜。

每个任务用同一用户Key读取当前目录/权限及结构化工具调用资格。首选不可用时自动选备用；两者均不可用时，按已审核且授权的目录选择其他候选。硬额模式不使用无法证明费用上界的候选。规划结构用官方DSH工具schema输出submit_plan，不依赖未经验证的供应商JSON模式。

规划专用输出1024 token，宿主结构化内容上限16KiB、最多8步骤。简单直接回答请求8192 token，不用规划额度截断答案。复杂计划超过限额时返回可验证的精简计划或合理缩小交付，不能吞掉字段后执行。真实glm-4.7规划质量、工具schema支持与价格上界仍需受控PT验收；本轮固定适配器探针不能证明这些事实。

### 15.2 模型提交的计划格式

```json
{
  "schemaVersion": "auto-plan-v1",
  "objective": "依据公开资料生成风险分析Word报告",
  "steps": [
    {
      "id": "research",
      "dependsOn": [],
      "role": "researcher",
      "requires": ["text", "toolCall"],
      "tools": ["web_search", "web_fetch"],
      "inputs": [{"kind": "user_goal", "ref": "goal"}],
      "outputKind": "evidence_bundle"
    },
    {
      "id": "analyze",
      "dependsOn": ["research"],
      "role": "analyst",
      "requires": ["text"],
      "tools": [],
      "inputs": [{"kind": "step_output", "ref": "research.result"}],
      "outputKind": "structured_document"
    },
    {
      "id": "export",
      "dependsOn": ["analyze"],
      "role": "writer",
      "requires": ["text", "toolCall"],
      "tools": ["document_export"],
      "inputs": [{"kind": "step_output", "ref": "analyze.result"}],
      "outputKind": "artifact_docx"
    }
  ],
  "deliverables": [{"kind": "artifact_docx", "from": "export.result"}]
}
```

宿主schema强制additionalProperties=false，验证工具/输出枚举、DAG无环、依赖存在、输入引用属于当前任务、能力已授权、产物类型及预算可覆盖。模型只给role/requires；具体模型由可信路由选择，或由已审核候选列表约束，不能写任意provider/URL/Key。

tenant_id、user_id、run_id、plan_id、授权版本、策略哈希、金额/次数上限、允许fallback模型/工具、输入SHA由宿主生成。模型不得提供或覆盖。校验后规范化JSON，计算plan_sha256并原子冻结。内存深冻结只作辅助；数据库不可变版本及hash为权威。

### 15.3 冻结与提示注入防护

联网正文、PDF/Office文字、CSV单元格、Skill附属内容、工具错误及历史引用均标不可信数据。它们可以影响分析答案，不能写计划表、改grant版本、调高额度、增加工具、替换模型候选或修改执行器参数策略。

执行每步验证plan_sha256、策略/授权版本、输入ref哈希、step_id和lease。动态工具范围来自冻结计划而不是模型当前文本。局部工具在tools/execute和宿主RPC两侧检查；工具schema隐藏不当作安全边界。敏感能力不因工具结果包含“系统消息/批准/换模型”而扩大。

自动恢复仅使用冻结的fallback和允许重试规则。需要改变依赖或交付结构时创建新不可变版本，重新验证，权限只能在原用户目标及原授权的交集内；旧计划保留。扩权需用户新增明确目标或设置授权，不能由外部内容触发。

测试覆盖网页/文件内伪造system/developer指令、JSON计划片段、tool-call文本、账单URL、恶意文件名、跨租户ref、恶意模型/域名、成本提高及隐藏unicode。逐项断言计划hash不变、无新许可、无越权执行。不能声称能保证模型答案完全不受语义注入影响；保障的是权限与副作用不可扩大。

## 16. 步骤间数据传递

小型标量/结构化结果可经原生tool/result进入Session；大文件、网页正文和报告保存为宿主owned不可变ref，不把所有字节塞入每次模型上下文。

每个ref包括kind、sha256、size、media_type、source/run/step身份和taint。模型只看到脱敏ref及必要摘要；真实路径、Key和数据库ID权限信息不下发。宿主按白名单字段读取输入，不运行JSONPath脚本、eval或模板中的命令。

步骤启动前校验依赖已成功及产物哈希。失败、取消、尚未提交的输出不得被后继步骤当成功输入。引用绑定同tenant/user/run；不得用任意URL或本地绝对路径代替owned ref。跨模型只传必要数据及源引用，防止不兼容图片或超出上下文。

工具产生的引用由宿主生成，模型不能伪造下载路径。产物发布先校验有效lease及授权，再持久记录并展示。最后交付检查实际文件可读/格式可解析，不能只相信模型说“已生成”。

## 17. 自动批准Python的独立安全门禁

设置页授权是必要条件，不是隔离已安全的证明。自动Python默认feature flag关闭，必须通过下表专项后才开启。之前可用csv_analyze等确定性工具自动处理；任意Python仍保留原精确确认，不把该过渡状态当自动分析已验收。

| 安全组 | 独立验证内容 |
|---|---|
| 实际权限 | 真实Linux/x64、非root、完整Landlock、seccomp及已冻结helper；不能用固定输出或macOS替身代替 |
| 文件 | 读取宿主密钥/其他租户/账单令牌失败；软/硬链接、父目录、proc/self/fd、路径替换与TOCTOU；写入/覆盖/rename/link/unlink失败 |
| 网络 | IPv4/IPv6 TCP、UDP、DNS、Unix socket、代理环境、继承FD及本地元数据地址均不可用于逃逸 |
| 进程/内核 | fork/exec、shell、ctypes绕系统调用、ptrace、跨进程signal、IPC、修改资源限制和提权路径 |
| Python导入 | sys.path/环境/启动文件污染、site和用户包、恶意输入当模块、pickle和动态导入；不把AST黑名单当唯一边界 |
| 资源 | 无限循环、内存/栈、输出洪泛、FD、压缩炸弹；CPU/墙钟独立监督器实际终止 |
| 生命周期 | 用户停止、授权撤销、lease丢失、worker SIGKILL、服务重启、迟到回调；无活跃遗留子进程、无后继模型派发 |
| 作用域 | 同租户两用户和跨租户并发；输入ref、代码哈希、策略版本、Run/call绑定错误时拒绝 |
| 审批证据 | system_policy与user_confirmation分开；一次执行许可不可重放；撤销后旧许可不可再次消费 |
| 注入 | 文件/网页让模型生成逃逸代码时仍被执行边界拒绝；无凭据、无任意宿主路径回显 |
| 对照 | 正常CSV/统计计算成功；拒绝例不是因解释器损坏；缺隔离时明确不可用，不降级到普通spawn |

主程实现测试与独立QA/安全复审分开留证，绑定代码、helper、策略和运行平台。该环境共享内核，不保证绝对消除所有侧信道；不把它宣传成虚拟机。不得为了完成AUTO而打开通用Shell或关闭现有强制隔离。

## 18. 媒体恢复：PT依赖与临时行为

当前代码已有按task_id查询的只读适配器：图片`/v1/tasks/{id}`、视频`/v1/videos/{id}`。这说明现有契约接缝存在，不证明每个账号/模型都支持，也不证明丢失task_id后能查回。本轮未调用PT验证。现有创建路径未据此确认支持幂等键。

| PT能力/证据 | 当前判断 | 未齐备前的临时做法 |
|---|---|---|
| 已有task_id的状态/结果查询 | 有现有代码与回归；目标账号仍需实测 | 仅按已保存task_id恢复；有界退避查询，不重建 |
| 创建幂等键 | 未取得端到端确认 | 未知受理后不重POST；本地operation_key只防本地重复，不能冒充PT幂等 |
| 按client operation/request key查询受理状态并找回task_id | 待PT明确提供及验收 | 无task_id时保留预留，标external_submission_unknown；交付其他可完成内容，后台等待可关联证据 |
| 明确“未受理”的响应语义 | 待PT确认哪些状态绝无任务/扣费 | 不能仅凭429/5xx/超时断定未提交，不自动重新创建 |
| 完整费用报价及最大受理金额 | 待PT提供或核对具体模型/参数 | 媒体缺可证明上界时，不进入金额硬帽自动创建范围；不造统一价格 |
| request/task与账单、退款关联 | 待PT同scope证据 | 不按模型名+时间猜关联；未知费用保持预留/未知 |
| 已受理任务取消/退款 | 待PT确认端点及保证 | 本地停止不声称供应商取消或退款 |

PT需明确：幂等键scope/TTL、相同键不同参数冲突、重放返回同一任务、并发行为、受理状态的not-found是否最终、账单延迟及查询保留期。没有这些合同，不能保证未知创建能自动无重复恢复。

这些PT依赖不阻塞文字/资料/报告AUTO的工程实现与隔离验证；正式硬额路径仍须满足第12节成本上界，不能自动降成计次模式。已满足报价和权限的正常媒体创建可单独验收；未知受理后的全自动重提保证与官方实扣硬帽保持待PT。用户无需手工排查接口，但不能因此隐瞒未知结果或重复扣费。

## 21. 新用户与新Key首次AUTO：必须解决的冷启动闭环

状态：方案要求，尚未实现。当前R34文字AUTO要求当前scope的runtime verification；scope同时绑定网关、userId和Key指纹。server仅在非AUTO路径调用文字验证记录；helper还要求单次模型响应及可信模型身份。新用户或新Key没有该scope验证时，可能全部候选RUNTIME_UNVERIFIED，形成先手动成功才能AUTO的循环。即使不同用户共用同一Key，也不应借别人的scope验证越过身份边界。

改进要求：已审核的模型/接口适配事实可以作为发行级资格，不能伪造为当前Key已经实测成功。首次AUTO允许受控bootstrap资格：先确认同Key目录权限、DSH配置、真实输入模态、接口适配、用户一次授权及任务预算，然后直接用用户这次真实任务执行首个合格候选。不是让用户手动选模，也不偷偷付费发Hello测试。

bootstrap与verified分开记录。首次任务成功后，只按实际模型attempt/可信响应和当前capabilityRevision写验证；失败或响应身份不符不晋级。候选失败按冻结fallback/重试规则自动继续；明确Key失效、额度不足或能力确实不足时才在聊天说明实际原因。不能为了冷启动取消所有能力检查。

验证范围仍为tenant/user/credential_scope/网关/模型/adapter/revision；更换Key、权限或能力版本变化后重新bootstrap。后台读已审核策略可以自动开始，但不能把别人的运行验证复制成自己的。首轮即使含多步/多次模型调用，也按具体attempt归因，不继续依赖旧helper的“整Run仅一次调用”条件。

首用验收必须包含：全新用户+新Key；旧用户换Key；两用户共用Key但不同scope；无本地缓存；目录首次失败后恢复；首选不支持而备用成功；正常多步任务成功后验证记录；中途失败/取消不晋级；模型revision变化；计费/授权/预算仍生效。默认聊天框完成，无手动选模、无预先聊天、无重登或用户调参。当前报告不得把该问题已修复写进上线状态。

首次AUTO冷启动补齐的工作量应计入第19节模型意图/资格接线与回归；建议在原5–7人日基础上预留0.5–1人日，当前包含该缺口的完整范围约5.5–8工程人日，独立QA仍另列。暂未整体开工。
