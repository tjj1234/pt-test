## 6. 每次交付说明与判定

每包使用同一模板：**版本/日期 → 相对上一包新增功能 → 用户可完成的流程 → 支持范围与限额 → 验收证据 → 仍不支持的范围 → 升级/回滚与遗留问题 → 可交付/不可交付结论**。版本绑定完整源码快照/发布清单、候选归档校验值与实际配置，不把 dirty HEAD 当完整源码身份。

交付前必须同时满足：新增功能从浏览器输入到可用结果闭合；旧功能回归通过；失败/权限/超限清晰；结果可按承诺持久化；同候选目标环境验证；无阻断该启用范围的安全问题；安装升级与回滚可执行。完整功能不等于立即完成整个 T，但不能拿内部函数或半截 UI 充数。

外部依赖明确分工：开发侧负责修目录、接模型/工具与 UI、收敛安全边界、冻结和验收脚本；目标维护者提供实际部署/诊断输出并执行已授权的切换；真实调用需要确定的 Key 能力范围和生成预算。现有一次文本、零工具试验范围不覆盖媒体验收，调用次数上限也不是费用上限。缺这些证据时继续本地开发，但不能签署功能交付结论。
