# 北极星模型资格阻塞修复计划

日期：2026-10-21。当前线上 r5 已完成 Google 登录、PostgreSQL 会话持久化和 HTTPS health 检查；所有模型仍显示“能力不确认”，因此受控试运行的模型验证尚未开始。此文说明修复计划与原重构任务包的关系；**不是新的服务器执行清单**。服务器命令仍统一维护在[受控试运行部署清单](北极星受控试运行部署命令清单-20261021.md)中。

## 结论

本次工作属于补齐原任务包 T06/T07 未完成的接线，不另建模型目录或权限体系。此前把 T06 能力模块说成“完全未接入 model-catalog”不准确：当前代码已把 `capabilities.cjs` 接入 `model-catalog.cjs`，`task-router.cjs` 也在后端执行 fail-closed。实际缺口是证据链不完整：服务端目录为全局服务级 scope，没有按当前用户已保存的 BYOK key 查询和隔离模型可见范围；目录字段没有可确认的 textChat／输入输出模态事实时保持 unknown；服务端也没有注入可信的本地策略、DSH adapter 和 runtime verification 记录。

## 工作顺序与任务包映射

### 当前进度（本地源码，尚未发布）

已完成第一段接线：`/api/models`、模型选择与聊天目录读取按认证用户解密 BYOK key，并按 user ID + key + base URL 的非秘密 hash scope 隔离目录及资格缓存；即使复用同一 key，也不会共用用户本地资格状态。移除了启动时用服务级目录 key 刷新全局目录的路径。PT `/v1/models` 返回某个 ID 只证明它出现在该 key 的目录响应中，不能单独证明该 key 有权调用；permission 保持 unknown，直到真实权限语义或可信授权证据确认。无用户 key 时只返回 unknown 的静态展示项，不将其标记为可聊。`/api/models` 附带每个模型的 router 拒绝码，UI 将显示具体阻塞阶段，便于定位目录、权限、能力、adapter、verification 或 modality 哪一项缺证据。

本轮继续补上只读诊断字段：模型投影会回传 PT 模型记录中出现的白名单字段名，以及 `capabilities` 内经格式过滤的键名；不回传任意原始值、key 或用户秘密。新版本部署并登录后，可从浏览器 `/api/models` 检查真实字段名，再依据字段来源与契约决定哪些能规范化成能力事实；这只帮助发现元数据结构，不授予 permission，也不绕过 router。

受控运行预算已收紧为每个 Run 最多 1 次模型请求、0 次自动重试、0 次工具调用、180 秒；这不是金额上限，PT 实际计费仍由余额监控，输入是无工具的简单文本问题。router 资格未通过前不会发起这次请求。

这段只修复“目录是否属于当前用户”的权限 scope，并提供字段名诊断，不会单独令模型变成可执行。PT 返回的实际能力字段语义、平台可见权限、可信本地策略、DSH adapter 与与 capability revision 绑定的验证记录仍需来源证据；当前仍保持 fail-closed，未触发生成调用、未改线上服务器，也未把 T06/T07/T03 标成完成。新加元数据字段诊断后需重新做静态检查；本轮未运行测试。

## 门槛与责任

执行顺序：**T06 用户 scope 与可信证据接线 → T07 API/UI 一致性 → 不付费资格检查 → 新候选包及部署文档 → 维护者逐条部署 → 单次受控真实验证。** 在此前，线上停止模型生成尝试；维护者无需改服务器配置、重启服务或重复尝试对话。K1–K3 只用于补充服务级目录凭证和缓存信息，不能替代代码接线或运行验证。

T06/T07 接线不重做 T03 持久 Run，不扩展到 T08/T09 多模态和文档解析，也不关闭任何任务包的整体验收。一次模型请求通过，只证明该模型、该权限 scope、该 adapter revision 的受控运行切片；不自动授权其他模型，不代表 T06/T07/T03 或一期生产验收完成。

## 与主重构任务的并行安排

四个工作位现按两个工作流并行：主 agent 负责线上最小可用闭环（T06/T07 资格接线、T03 单次受控 Run、候选发布和证据结论），并负责跨模块集成；子 agent A 负责 T12 记忆/上下文预算的隔离实现切片；子 agent B 负责 T15 CI 与验收矩阵差距证据；子 agent C 修订部署文档里的 K1–K3 诊断适用性并说明用户是否需配合。三项子任务不得改主 agent 的共享 T06/T07 文件，也不触发服务器操作、模型调用或测试；主 agent 集成前审阅并补 targeted 静态检查。工作位上限是主 agent 加最多 3 个子 agent。线上闭环和原任务包持续并行；一次线上答复仍不替代整包开发或验收。

当前用户协助项：新候选包准备好后，执行部署清单中的服务器命令并回传输出；真实验证继续使用已约定的单次受控额度。不需要在聊天中提供任何 key。当前不要求执行服务器命令。
