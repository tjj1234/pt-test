# T16 Linux/amd64 dependency closure gate — 2026-10-23

## Accepted target and method

The target platform is fixed to Linux/amd64 (`linux` / `x64`), with Node.js >=22.19.0 required by the locked production dependency engines. Dependency closure is resolved with exactly locked `@npmcli/arborist@8.0.5`, then recorded as a deterministic manifest containing each production package's lock identity, declared Node engine, and each package file's relative path, type, mode, size, and SHA-256. The helper checks every installed production package's `engines.node` using exactly locked `semver@7.8.5`; optional packages not installed on this platform are not treated as runtime requirements. Nested `node_modules` trees are excluded from a package walk because Arborist enumerates them as separate package nodes. Absolute, dangling, or package-escaping symlinks fail closed. The manifest binds exact `package.json`, `package-lock.json`, and `.npmrc` hashes and records the generator Node/Arborist versions. `--check` accepts another Node version when all locked production engines pass; it ignores only the checker runtime version field, while recomputing and comparing every dependency identity and file hash. Sorting uses JavaScript's stable code point string order.

Arborist itself supports Node `^18.17.0 || >=20.5.0`; this build-tool range does not set the application's runtime minimum. The locked production closure requires Node `>=22.19.0`, as checked against every installed production package's declared engine. Arborist is a build-time `devDependency` and is excluded from the production dependency closure. Arborist compares installed and lock graph identities (location, name, version, resolved URL, and integrity); per-file hashes bind the bytes observed after a clean locked `npm ci`. The manifest does not independently re-hash package tarballs against SRI. Required unresolved edges, unlocked or mismatched packages, missing required packages, extraneous production packages, linked packages, and unsafe file entries stop generation. Clean `npm ci` is the install provenance boundary; the manifest records the resulting installed bytes.

## Current implementation and evidence boundary

Added `scripts/northstar-dependency-closure.cjs` and exact Arborist `8.0.5` and semver `7.8.5` pins in `shell/package.json` / `shell/package-lock.json`. Its release CLI is deliberately Linux/amd64-only: `--write <path>` creates a new manifest without overwriting an existing one; `--check <path>` requires identical closure content while allowing the checker Node version to differ. Local helper regression **9/9 PASS** covers platform and Node gates, installed-package engine checks, cross-version comparison behavior, path validation, file hashes, nested dependency separation, symlink escape rejection, production/dev edge traversal, and rejection of extra production packages. An independent review found the extra-package case missing in the first draft; it is now fail-closed and covered by a regression.

An initial Darwin inspection found three required peer edges from the locked DSH UI packages: `use-sync-external-store -> react`, `@tanstack/react-virtual -> react`, and `@tanstack/react-virtual -> react-dom`. The compatible exact pair `react@18.3.1` / `react-dom@18.3.1` was added to the future shell dependency lock, satisfying those edges without weakening Arborist's peer checks. A clean Linux/amd64 Node 20.20.2 install emitted `EBADENGINE`: production `@earendil-works/pi-ai@0.82.1` requires >=22.19.0 and `commander@15.0.0` requires >=22.12.0. The Node gate therefore follows the strictest locked production engine, >=22.19.0; the current candidate-32 runbook's 20.6 minimum is lower, while its target server installation record shows Node 24.22.0. The Node 20 run was stopped before manifest generation and is not evidence. A Darwin/arm64 exploratory scan before the extraneous-package guard resolved the graph and inventoried **468 production packages / 30,066 files**; it is historical only, does not pass the strengthened check, and is not a target artifact. `legacy-peer-deps=true` remains part of the hashed install policy, while required peer edges are checked against the actual graph.

## Linux/amd64 execution

Executed in an isolated `node:22-bookworm-slim` container forced to `linux/amd64`, reporting Node `v22.23.4`, Linux `x64`, npm `10.9.9`. The project was mounted read-only and copied into a disposable container directory. First clean `npm ci --no-audit --no-fund` installed **621 packages** with no EBADENGINE warnings; `--write` passed with **472 production packages / 30,091 files**. The helper checked all **194** installed production `engines.node` declarations; the strictest were `@earendil-works/pi-ai@0.82.1 >=22.19.0` and `commander@15.0.0 >=22.12.0`. A second `npm ci` in the same disposable copy rebuilt `node_modules` from the lock, after which `--check` independently passed with identical counts and package-lock hash. After the checker was made Node-version tolerant, a fresh Linux/amd64 clean install also passed `--check`; it reported both generator and checker as `v22.23.4`. Cross-version acceptance is covered by a helper regression that varies only this metadata field and confirms changes to package hashes or lock hashes still fail. A live `--check` on the historical target Node `v24.22.0` has not run; pulling that Docker image ended with a Docker Hub EOF. The manifest is retained at `T16-dependency-closure-linux-amd64-node22.23.4.json`, SHA-256 `bec48d7e0eafc6662933f7f1954317c3f68d0c1df7e7d3ad4069d225e5653dbe`; package-lock SHA-256 is `795b97b08935f4320c8d2567ff101d051b2e643c316093513f2031c7ffc9f912`.
