# T10 artifact tenant download boundary audit — 2026-10-22

**Finding:** the current `/api/artifact` route follows a workspace symlink and can return another tenant's artifact to the requesting tenant. This is a direct failure of T10's preview/download boundary requirement and needs a production fix before this route can be considered safe. No production code was changed in this audit.

In `shell/server.cjs:1723-1747`, the route derives the authenticated tenant's workspace and computes `artAbs` with `path.resolve`. It compares that lexical path with `artRootReal`, but never resolves `artAbs` to its actual target. It then calls `fs.statSync(artAbs)` and `fs.createReadStream(artAbs)`, both of which follow symlinks. Existing scanner code in `shell/runtime/artifacts.cjs:132-140` only recognizes `Dirent.isFile()` entries and therefore does not provide protection to the independent download route. Existing `tests/regression/artifacts-test.mjs` checks relative-path helpers and scanning; it does not exercise authenticated HTTP download or symlink containment. The v2 T10 requirement explicitly calls for preview/download to prevent tenant escape and symlink access (`docs/北极星一期生产级重构完整任务包-v2.0.md:296-304`).

The same read-only pass found two more bounded gaps. Artifact fallback collection is based on `collectRoundArtifacts(workspace, sinceMs)` (`shell/runtime/dsh-adapter.cjs:92-95, 814`), which scans the shared tenant workspace by modification time and does not receive a Run or call ID; this cannot satisfy T10's requirement that workspace scanning be only a discovery fallback and must not misattribute concurrent A/B outputs. Also, required `.csv` and `.xlsx` downloads are not supported by the current `ARTIFACT_EXTS` / `artifactKind` whitelist (`shell/runtime/artifacts.cjs:24-41`). For persistence, normal chat messages save reply, steps, media, and report but not the fallback `r.artifacts` array (`shell/server.cjs:916-929`); the durable executor captures that array in `finalPayload` (`server.cjs:692-699`), while `shell/tasks/execution.cjs:110-115` copies only status/error fields into the persisted done event. Tool-time `artifact` events may persist as Run events, but the scan-discovered final list has no durable artifact registry/reopen path in the inspected migrations or task store. These additional findings are static code-path observations, not end-to-end reproduction in this slice.

Added `tests/regression/t10-artifact-tenant-symlink-audit-test.mjs`. It starts an isolated local shell server with a temporary PGlite database and two fixture tenants, places a private PDF in tenant B's workspace, and creates `tenant-A/leak.pdf` as a symlink to it. The test authenticates as A and requests the artifact through the normal HTTP route. It expects a denied/not-found response and no private body.

**Reproduction and baseline:** `node --test tests/regression/t10-artifact-tenant-symlink-audit-test.mjs` — **1 test failed as expected**, actual HTTP status `200`, body `tenant B private artifact`. Existing `node tests/regression/artifacts-test.mjs` passed **75/75** and `node --test tests/regression/artifacts-boundary-test.mjs` passed **1/1**; these cover helper/scan/path normalization, not the authenticated streaming route. This is a local fixture only: no online host, paid call, or production credentials were used. Test cleanup removes the temporary runtime, database, key, and workspaces.

**Minimum next step:** change the serving boundary to open only a regular file whose resolved path remains beneath the authenticated tenant workspace, with race-safe no-follow semantics; then rerun the new HTTP test and existing `tests/regression/artifacts-test.mjs` / `tests/regression/artifacts-boundary-test.mjs`. Until fixed, T10/AC11 should retain their existing status; this finding alone is not a complete T10 or AC11 assessment.

## Remediation follow-up — same date

The initial finding above is historical and was not the final state for this date. The route now uses `shell/runtime/artifact-open.cjs`: on Linux/Darwin it binds POSIX `openat`/`close`, walks each workspace and tenant directory component with `O_DIRECTORY|O_NOFOLLOW`, opens the leaf relative to the pinned directory descriptor with `O_NOFOLLOW`, and requires a regular file with link count 1. This closes the directory replacement window identified in the review and rejects hard links. The HTTP audit now covers authenticated GET/HEAD, leaf and intermediate symlinks, hard links, and unauthenticated access; the helper test deterministically swaps a traversed directory for a symlink. Local targeted verification passed 6/6 Node tests and the existing artifacts helper passed 75/75. This is local-platform evidence; Linux target-host behavior still awaits candidate deployment. T10/AC11 remain partial because persistent Run/artifact provenance, concurrent output attribution, same-UID tenant isolation, and required export formats are outside this fix.
