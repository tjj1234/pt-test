# T09 CSV 来源上下文限定验证 · 2026-10-19

结论：CSV 上传校验、确定性单元格来源、宿主上下文与历史版本保护切片通过独立受控验证；T09/AC10/21 整体验收未完成。环境为本机 Node v24.14.0、临时 PGlite、真实 HTTP/session、受控能力目录与 tenant dry-run，无真实供应商模型/付费请求，无生产 profile 或数据迁移操作。

| 行为 | 实现与独立证据 |
|---|---|
| CSV 原值与来源 | `csv-parser.cjs` 保留空字符串、字符串0、前导零、重复行、quoted multiline及逻辑/物理坐标；7组fixtures通过。修复TextDecoder重复去BOM造成第二U+FEFF丢失。 |
| 来源身份 | `csv-source.cjs` 按原bytes完整SHA256+ref hash+行列生成token；深冻结与私有品牌拒绝伪造source。不同上传来源即便bytes相同也不同引用身份。 |
| 预算与覆盖 | 仅输出完整cell前缀，metadata声明总行列/cells/bytes、shown/omitted/truncated/firstOmitted；metadata放不下明确拒绝，不退回raw slice。 |
| 上传与读取 | 坏CSV在落盘前400拒绝；合法BOM/CRLF原bytes保留。宿主验证租户、realpath、symlink、NOFOLLOW、打开FD inode/size，有界读后核对capture hash/size。 |
| 历史保护 | 所有文档上下文校验先于normal/regenerate/branch首次写历史；新用户消息保存受控documentEvidence。未改附件可再生；同长度合法内容变更触发CHAT_ATTACHMENT_CHANGED，历史逐字段不变，runner无新增。 |
| 遗留历史 | 缺documentEvidence的旧文档消息再生返回DOCUMENT_SNAPSHOT_REQUIRED，需要重新上传发问；不能用当前请求evidence冒充原历史版本。 |
| 失败真相 | 解析/额度失败明确拒绝，无悬空user或提前截断；Run附件来源事件的持久化异常保留原store/lease错误，不伪装成CSV错误。 |

验证命令：

```sh
node --test tests/regression/csv-parser-test.mjs tests/regression/csv-source-test.mjs
node --test tests/regression/csv-document-http-test.mjs
```

独立 parser/source **14/14 PASS**；独立 HTTP **1/1 PASS**（含多项HTTP断言，不能表述为14+多项独立测试）；HTTP loopback在沙箱内EPERM后按批准前缀重跑。上下文1200字符夹具验证30行60格明确截断，无完整表格覆盖假象。临时数据库、文件和合成租户workspace均由夹具清理，无宿主依赖安装。主Agent负责server集成；不同子Agent负责source实现、parser/HTTP反例及交叉审查。

边界：来源hash不代表模型答案引用正确性或事实验证；尚无点击定位来源UI、跨文件检索、确定性计算/公式来源、XLS/XLSX、PDF/OCR、Office/ZIP、派生索引删除或真实模型素材验收。同uid恶意写入的OS隔离与生产PostgreSQL多进程不在本切片结论内。仅对上传CSV进行结构校验不代表文档中的指令可被信任。
