# T09 deterministic CSV analysis slice — 2026-10-22

**Result:** added an isolated deterministic calculator for an explicitly selected CSV column. It computes `sum`, numeric `count`, `min`, and `max` with exact decimal arithmetic and returns the source coordinates of every contributing cell. This closes only a reusable calculation primitive; it is not connected to chat, upload HTTP, Run/tool routing, UI, or persisted attachment flows. T09 remains `partial`; AC10 and AC21 remain `untested`.

`analyzeCsvColumn(source, { operation, column, startRow })` accepts only immutable `buildCsvSource` results, uses 1-based coordinates, and never guesses headers or types. The caller chooses the first data row. Empty-string cells and ragged rows are omitted from arithmetic but listed separately as `ignoredEmpty` coordinates and `missingRows`; a numeric zero contributes; repeated rows are counted independently. A selected non-empty value must match a plain signed decimal with a dot separator; leading zeroes are accepted and retained in the source, while output is normalized exactly (for example, `0003` → `3`). Dates, units/currencies, whitespace-padded values, exponent notation, and locale-specific separators fail with the offending cell coordinate rather than being coerced. To enforce the user-selected rule A without locale inference, values shaped like `1.234` (1–3 nonzero-leading integer digits followed by exactly three fractional digits) are rejected because they can also represent grouped integers; values such as `0.125` and `1234.567` remain accepted. The user selected rule A: continue rejecting ambiguous date, unit/currency, and regional formats without inventing conversions; use real trial uploads to decide any later extensions. Regression rejects examples including `01/02/2026`, `5 kg`, `5 EUR`, `1,25`, `1,000`, `1.234,56`, `1.234`, `12.345`, and `123.456`. A range containing no numeric values fails instead of returning a misleading zero. Each result includes operation, selected column/range start, exact result string, contributing count, input-cell coordinates, and empty/missing cell coordinates.

Resource bounds are 10,000 parsed rows per analysis, 128 decimal digits per value, and 18 fractional digits. The CSV parser continues to enforce its existing byte/cell limits before analysis. The operation is linear in the selected column; no arbitrary formulas or scripts execute. `assertCsvSource` exposes source authenticity validation for this sibling module and rejects deserialized/forged objects.
