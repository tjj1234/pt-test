# Gemini 独立任务包：文档导出候选模块（Word/PDF/Excel）（2026-10-26）

**目标**：做一个独立的文档生成候选模块，接收结构化数据（标题、段落、表格等），生成 Word(.docx)、PDF、Excel(.xlsx) 三种格式文件。此任务只做生成能力本身，**不接入**产品对话流程、不接 Run、不宣称任何业务功能已完成。主 Agent 与子 Agent 在你交回前不编辑本包指定文件。

## 必须解决并验证

1. **依赖库选择要可审查**：选用成熟、持续维护的开源库生成三种格式（如 docx 生成、PDF 生成、xlsx 生成相关库），要求：MIT/Apache 等宽松许可证（不可用 GPL 类传染性许可证）、纯 JS 或无需系统级编译依赖（避免部署环境装不上）。在交付报告里写清楚选了哪个库、版本、许可证，供人工复核。
2. **输入必须是结构化数据，不做格式解析**：模块只接收明确的数据结构（如 `{title, sections: [...], table: {headers, rows}}`），不负责从别的格式（如从一段非结构化文本）反推结构。
3. **数据缺失/字段异常时必须 fail-closed**：遇到必填字段缺失、表格列数不一致等情况，拒绝生成并返回明确错误，不得生成一份看起来正常但实际缺数据的文件；降级或跳过的内容必须在返回结果里明确列出（比照"降级可以，但必须让下游知道"的原则，不能悄悄丢数据）。
4. **必须有资源边界**：最大行数/单元格数、最大文件大小、生成超时时间，三者都要有硬上限并可配置，超限时拒绝生成并返回明确原因，不能无限处理导致挂死。新增覆盖超限场景的测试。
5. **必须防范 Excel 公式注入**：任何写入 Excel 单元格的字符串，如果以 `=`、`+`、`-`、`@` 开头，必须转义或加前缀处理，防止被 Excel 当公式执行（这是电子表格生成的已知真实漏洞类型，必须有专项测试覆盖）。
6. **生成的文件不得包含可执行内容**：不生成宏（VBA）、不嵌入外部链接自动加载的内容、不自动拉取任何外部资源写入文档，避免生成的文件成为后续的安全隐患。
7. **输出文件必须真实有效**：不只是"字节格式正确"，要能被 Word/Acrobat/Excel 真实打开不报损坏（可用对应格式的校验库或已知的最小化开合校验方式验证，报告里写清楚怎么验证的）。
