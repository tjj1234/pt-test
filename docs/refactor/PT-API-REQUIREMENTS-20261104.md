## 1. 合作目标与边界
北极星复用锁定DSH的Agent、模型选择、工具、Session、Skill与工作流能力；PT提供模型推理、媒体与资产任务、模型资格、平台限额及真实计费接口。北极星负责用户界面、租户权限、Run/操作账本、结果存储与DSH接线。PT不需要重写DSH或北极星的审批、文档编辑和电脑执行器。
北极星内部将PT收敛为一个供应商adapter，内部按能力分接口；不要求PT将所有业务压成单一万能HTTP endpoint。现有兼容端点与认证不得破坏。其他供应商由北极星后续适配，不属于PT开发范围。
本文“新增/补充”均为需求分类，不表示PT当前一定没有。PT需逐条回复已支持、需配置、需开发、替代方案或不支持，并提供端点/模型/权限/样本证据。文中标“建议”的路径和字段在评审后冻结；未确认前不能当成PT当前API。

## 4. PT-01 公共契约（P0）
### 4.1 认证、标识与隔离
每条endpoint说明接受BYOK API Key、平台登录token、短期令牌中的哪类，格式是否Bearer、scope、过期/撤销与刷新方式。Key ID应稳定不敏感且可唯一绑定授权范围；掩码字符串若不能唯一识别需新增opaque ID。账号A不得通过改key_id/task_id/asset_id读取账号B资源；账号token访问多Key必须校验归属，禁止靠客户端过滤。
北极星调用携带建议字段/头：X-Client-Request-Id（每次HTTP尝试）、client_operation_id（一次逻辑付费操作）、可选traceparent；业务Run ID仅作opaque元数据，不包含用户文本/邮箱。PT生成request_id；异步任务生成task_id；消费产生consume_id。PT需确认字段上限、保留期与可检索性。不要求同一逻辑操作的每次查询共享HTTP request_id。
### 4.2 响应、错误与流式
旧控制面保留code/data/msg；新端点提供OpenAPI明确外层，禁止同一路径随机混用。标准推理兼容端点不强制加自定义JSON外层破坏SDK。所有响应提供可读取的request_id，流式在响应头及可行事件返回；流中错误明确终止状态，不以正常finish掩盖失败。
错误至少包含稳定error_code、message、request_id、retryable、retry_after_seconds（适用）、operation/task引用（适用）。retryable仅表示允许重试的类别，不授予北极星自动重提付费操作。
| HTTP/业务分类 | 最小区分 |
|---|---|
| 400/413/415/422 | 参数、输入过大、格式、语义/组合不支持 |
| 401/403/402 | 凭据无效、权限/模型停用、余额或额度不足；必须用细分码区别权限与下架 |
| 404/409/410 | 资源不存在、幂等冲突/状态冲突、已过期；跨账号可统一404防枚举 |
| 429/503/5xx | 额度限流、容量暂不可用、上游异常；标明是否可能已受理 |
客户端不能从500或断线推断“未扣费”。返回acceptance_state=not_accepted/accepted/unknown或等价可查询证据；不得将unknown当failed_final。需定义UTC时间、字段空值、大小/单位、版本及兼容策略。
### 4.2.1 AUTO候选切换：未受理与确定零费用须同时可证（P0确认）
北极星新增规则：先用当前Key目录资格预筛，明确无资格不调用；只有PT已确认适用语义的401/402/403类拒绝，且实际证据同时证明**未受理、确定零费用**，才允许AUTO选择下一个合法候选。HTTP状态码、retryable=true、not_accepted单字段均不能单独证明免费。

| 请PT明确确认 | 必须给出的语义/证据 |
|---|---|
| 适用范围与版本 | 数据面base/endpoint、模型/渠道/Key scope、稳定error_code、语义版本/生效及失效；不能用目录接口403推断推理拒绝免费 |
| 未受理 | acceptance_state=not_accepted或等价可信证据；说明网关/上游是否均未创建任务/未开始推理，及可查询关联ID |
| 确定零费用 | 提供独立费用状态/错误码保证或等价字段，明确无网关/上游/额外工具费用；pending/unknown/估算0/暂未出账不能等于零费用。字段名由PT确认，本文不伪定现有API |
| 歧义与流式 | acceptance与费用字段冲突、已输出内容/工具或任务受理证据存在时，不得按零费用拒绝处理；确认后保留可审计来源 |
| 默认关闭与排除项 | 未获PT确认前，任何已发执行尝试失败都不自动换候选；超时/5xx/429/无响应/流中断按未知受理，不因Retry-After自动重提 |

状态：待PT官方确认。本段为需求，不是PT已签收事实；本地fixture可验证策略，不能解锁真实环境切换。目录同步失败不抹last-good快照；当前Key资格unknown不自动收费探活。执行接线与验收见[08补充契约](AUTO-08-CATALOG-FALLBACK-CONTRACT-20261104.md)，目录自动维护见[17任务包](REFACTOR-GOVERNANCE-PACKAGE-20261103.md)。
### 4.3 数值与版本
计费小数建议十进制字符串；既有整数credits字段保留兼容。明确精度、舍入层级、单位和价格生效时间。未知usage/cost为null或显式known=false，零仅表示已确认零。新增可选字段保持向后兼容，破坏性变更走版本路径；提前通知周期双方确认。

## 5. PT-02 模型能力与资格（P0）
优先扩展现有/v1/models或另给能力查询，不强制替换。返回模型事实与当前凭据授权两部分，禁止“目录列出”等同可执行。
| 字段组 | 必须说明 |
|---|---|
| 身份/版本 | model_id、provider、display_name、model_revision（若可得）、availability、deprecated_at/replacement |
| 任务/端点 | text_chat、image_understanding、image_generation/edit、video_generation、ASR等任务；对应method/path/API方言 |
| 输入输出 | 模态、MIME、最大文件/张数/帧/音视频时长/总大小；上下文/输出token、是否多轮 |
| 推理/工具 | 精确reasoning_efforts、tools/tool_choice/并行工具、JSON schema能力及限制 |
| 参数schema | 必填/默认/枚举/范围/互斥/模式组合；不靠模型名猜参数 |
| 当前Key资格 | allowed、reason_code、quota_scope、requires_agreement、checked_at、可选eligibility_expires_at（仅资格缓存，如适用）、capability_version；协议本身无有效期 |
| 价格引用 | pricing_version、计费维度和价格查询引用；预估不等于实扣 |
验收：有权限/无权限/过期/下架/未知模型逐项可区分；服务端拒绝不支持的参数而非静默忽略。模型真实执行验证由北极星另行记录，PT目录不代填runtime verification。

## 6. PT-03 对话、工具、推理和图片（P0）
保持现有DSH所用兼容API：逐模型声明支持Chat Completions/Responses/其他方言，给真实请求响应示例。测试普通多轮、SSE、工具调用参数分片及tool-call ID、tool result续轮、推理档位、图片字节/URL输入、取消断线和错误。
支持的参数应传递，不支持应具名失败；不能接受reasoning_effort后无声丢弃。requested_model与可证实的resolved_model分别返回；若上游不披露则resolved_model=null，不伪造实际身份。usage注明输入/输出/缓存读写/推理token是否包含与可计费性；SSE中断usage无法取得保持未知。PTY/本地执行不属于PT。
JSON结构化输出按模型声明支持级别，schema不支持给明确错误；原生server-side tools若有，说明额外调用和账单，不可隐式执行未授权联网/代码任务。

## 7. PT-04 付费任务：提交、查询、幂等、取消（P0）
建议契约适配到现有标准/v1/images/generations、/v1/videos及任务接口，不要求统一改路径。
| 操作 | 必须行为 |
|---|---|
| 提交 | 接收Idempotency-Key或client_operation_id；鉴权通过后原子占位并绑定规范化请求摘要 |
| 重复同参 | 同账号/Key作用域同操作返回原task/状态，不新建、不重复扣费 |
| 重复异参 | 409 IDEMPOTENCY_CONFLICT，不覆盖原任务 |
| 未知提交恢复 | 可按client_operation_id查询是否受理；只知道task_id才能查询不足以解决响应丢失 |
| 查询 | accepted/queued/running/succeeded/failed/canceled/expired等状态及合法转换、时间戳、可选进度和结果/错误 |
| 取消 | best_effort/confirmed/not_supported明确区分；单独返回billing_state，取消/超时不承诺免费 |
| 结果过期/删除 | 任务状态与结果可用性分开，成功任务结果不可下载不回退成未执行 |
幂等保留窗口由PT填写，须覆盖最大任务时长+结果未知核对窗口；若暂不支持，PT明确风险和替代查询，不能承诺“刚好一次”。
建议异步响应：task_id、request_id、client_operation_id、status、submitted_at、billing_state、poll_after_seconds。最终查询补outputs[]、usage、cost/consume引用、completed_at。Webhook可作P1优化，必须验签、时间窗口、防重放、稳定event_id、乱序/重发处理；轮询始终可用。
验收关键：服务端已受理但客户端未收到响应，后续只查询能找到唯一原任务与消费；禁止靠再次提交碰运气。

## 8. PT-05 资产输入与输出（P0/P1）
优先既有上传/引用协议；需要asset_id、owner scope、MIME、size_bytes、SHA256（可提供时）、processing/status、可选asset_expires_at（仅资产资源如适用，非签署协议）、可用任务模式。签署状态仅agreement_accepted=true/false，无有效期/续签；asset_library_enabled独立表示资产库启用，不能混同未签署。按PT已提供协议处理，不新增协议scope/revision要求。上传支持单次先交付，大文件分片/断点续传P1。
远程URL输入如支持，说明可达协议/大小/重定向/授权；私网和凭据URL不得成为访问旁路。多模态参考资产明确角色，如first_frame/last_frame/reference_image/reference_audio，禁止仅以数组位置猜测。
输出包含角色/MIME/大小/尺寸/时长、URL或资源ID、下载认证方式、可选SHA/有效期。PT现有结果URL长期有效为已接受业务假设，不新增CDN前置；需确认删除/撤销例外和允许下载重试范围。北极星下载失败只补取已有结果，不再次生成。

## 9. PT-06 消费、余额、账单、价格（P0）
复用现有接口。对/v1/logs/query建议新增有界start_time/end_time（UTC，左闭右开）、key_id、request_id、task_id、client_operation_id、model_id、status、cursor、limit；默认/最大跨度与limit由PT给出。若旧接口data为单条，另给版本或兼容扩展，禁止直接破坏旧调用。
分页要求稳定排序(consume_time,consume_id)、opaque cursor、next_cursor、has_more、snapshot/data_as_of；迟到记录、同秒多条、查询期间新增/冲正不漏不重，消费ID稳定。查询结果保留现有consume/request/task/model/usage/billing，补logical operation关联及requested/resolved模型的证据语义。
| 补充字段/语义 | 要求 |
|---|---|
| usage | token/图片/秒/字符/音频输入输出等实际维度；缺失不可按0 |
| billing state | pending/finalized/refunded/adjusted/unknown或等价；失败也可能有费 |
| 计费过程 | 计价版本、数量/单位/费率、折扣、舍入规则、实扣credits；退款用新调整记录并关联原记录 |
| 余额 | Key配额和账号余额分别说明；缓存标志/统计时间；Key ID选择和token权限明确 |
| 汇总 | 时区、起止包含性、当前水位、最终结算延迟；可按Key/model/type过滤；与明细口径一致 |
| 价格目录 | 版本/生效时间、缓存/推理/输入输出/分辨率/时长等维度；如仅网页提供，先给可引用版本和变更通知 |
credits和USD不默认固定换算；费用估计与实扣分别保存。PT给常规/最长出账延迟与查询保留期，超时未出账保持pending/unknown。验收跨页/迟到/退款/多Key隔离及按request/task/operation唯一关联。

## 10. PT-07 配额与容量（P0）

请评估5/10/25/50并发混合任务的可供额度与价格，区分聊天长连接、视频在途与ASR；这是申请档位，不是已承诺并发。PT确认排队最长时间、任务保留、状态查询限流、突发策略、扩容联系人/周期、维护/下架通知渠道。压测需双方明确账号、模型、次数、费用和停止条件。

## 11. 新模态详细契约
以下建议为能力级契约；PT可映射成熟标准端点，但须提供逐字段OpenAPI，不能只给模型名称。

## 12. 安全、数据与服务约定
明确输入/输出/日志保留期、是否用于训练、上游转发范围/地域、删除与备份清理语义；敏感授权以实际用户同意和服务协议为准。测试使用合成数据。
资产/任务/账单权限在服务端校验；token撤销和Key禁用后新请求拒绝，既有任务查询/账单保留规则明确。日志脱敏不输出Key、登录token或带签名URL。
PT提供可用性、首响应/任务完成延迟、支持响应与事故通知的建议目标，双方约定后作为SLA；本稿不虚设已承诺99.9%。状态查询和消费接口有独立限额，避免恢复流量挤占推理。
