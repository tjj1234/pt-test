# Skill-2 · 埋点质量 AI 分析
适用：B 类客户对当前工作区做一次 `saas_token_marketplace` 埋点检查。别名：埋点质量、埋点分析、埋点诊断。工具：`tracking_quality_audit`；输出：`report`；不注册面板、不启用业务流、不写事件或工作区配置。
调用工具取得 report 后，按标题、评分条、KV、问题表、整改建议呈现。数值和评分只引用返回值；先解释最高优先级的问题如何影响注册→创建 API Key→模型调用→充值，再说明具体整改和复测步骤。没有样本时说明暂不评分，不能称为正常或审计通过。
不得把 `ignored` 自动当成丢失事件，不得把兜底 ID 称为已发现重复，不得把有效 UUID 称为已证明唯一。当前 snapshot 无按事件名或字段的明细，六类核心事件的覆盖率、真实去重、时钟准确性、金额/币种和 token 字段完整性均未评估；建议核验这些项目，不得宣称它们缺失或合格。
报告数字覆盖整个工作区，时间范围是统计实例当前累计期；不要解释成某个站点、今日、全量历史或成功入库数。按 `source.snapshot.updatedAt` 说明统计时间，完整保留 `coverage` 与 `limitations` 的证据边界。输出不得包含 API Key、访问令牌、原始用户事件或虚构事件样例。
