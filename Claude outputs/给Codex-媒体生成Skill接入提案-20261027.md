# 给 Codex：媒体生成改用现成 Skill 封装（powertokens-video）的提案（2026-10-27）

## 背景

北极星原生的图片/视频生成任务目前处于挂起状态。与此同时，另一位同事用别的 agent（wb）已经做出一个独立验证过的 Agent Skill——**powertokens-video**，仓库：https://github.com/tjj1234/powertokens-video

仓库结构：`SKILL.md`（Agent Skill 标准清单，描述用的是 tool-agnostic 触发词，不绑定具体 agent）+ `pt_video.py`（全部生成逻辑所在的引擎，CLI/SKILL/MCP 层都不应重复实现这部分逻辑）+ `mcp_server.py`（MCP 封装）+ `docs/pitfall-archive.md`、`docs/publish.md`（踩坑记录与分发说明）。

**已有真实出片验证**（不是仅接口测通）：
- 视频 1 次（`wan3.0-video` · 480p · 5s · 2.1MB）
- 图片 1 次（`image-01` · 1:1 · 245KB）
- Seedance 全链路打通：协议签署流程 ✓、文生视频走 `media-text` 提交 ✓、图生视频用真实 `asset://` 引用 ✓、素材上传闭环 ✓——只差充值，预扣费校验前的全部步骤均已验证通过

## 提案

**不在北极星内重新造生成逻辑，直接把这个 Skill 接入北极星已有的 DSH Skill registry 机制。**

这正好对应你在复用审计里给出的结论——"Skill 文件发现与加载：底层已可复用；模型入口关闭，租户发布版本不可信"，归入"是，PM 技能发布包"这一类、本期可做。powertokens-video 就是第一个现成的、已验证过的候选内容，不用等北极星自己从零开发媒体生成能力，也不用你们重新踩一遍 PT 网关这边的坑——这些坑已经在仓库的 `docs/pitfall-archive.md` 里记录得很细（API 语义不可信、轮询设计、Key 泄漏防护、Seedance 协议前置条件等）。

## 接入前需要你确认/补齐的 5 个缺口

这个 Skill 目前是"一个工程师手动用的 CLI 工具"的成熟度，不是"多租户产品里自动调用的功能"的成熟度，差距具体在这几点：

| # | 缺口 | 现状 | 为什么接入前要处理 |
|---|---|---|---|
| 1 | **零单测 + 轮询无熔断** | 文档已知短板：查询连续返回非 200 / 状态读不出时没有计数熔断，会静默空转到 600s 超时 | 单人手动用能自己观察卡住；产品里多租户自动触发，网关一抖动可能大量请求同时空转到超时，体验上就是"等十分钟才报错" |
| 2 | **错误分类未做** | 网关原始报错文本直接透传（如 403 同时代表余额不足/无权/Key 失效三种含义，未拆分） | 工程师能看懂原文，普通用户看到这种报错会不知道该怎么办 |
| 3 | **Key 注入方式要对齐 BYOK** | 读本地配置文件 `~/.config/powertokens-video/config.json`，可用环境变量 `PT_VIDEO_CONFIG` 覆盖 | 北极星的 BYOK 原则是"环境变量优先于文件、按次注入触发者自己的 key"；需要确认这个 Skill 的环境变量覆盖机制能严格做到"每次调用用触发者自己的 key"，否则多租户场景下有串 key 风险 |
| 4 | **Seedance 协议签署引导需要搬进产品 UI** | 目前是 CLI 层的文字引导（检测未签署 → 提示去 PT 后台签），Skill 本身不代签 | 这个设计是对的（不能代用户签协议），但引导文案目前只在 CLI 输出，接入北极星后需要在产品界面里重新呈现这段引导 |
| 5 | **asset id 跨账户可读** | 实测证实：PT 的素材库 asset id 没有账户级隔离，知道 id 就能在自己的 key 下引用生成 | 不是这个 Skill 的 bug，是 PT 平台行为；但北极星以后如果涉及素材展示/复用，设计上不能假设 asset id 天然租户私有 |

## 需要你给的东西

1. **可行性评估**：把这个 Skill 接入北极星现有 DSH Skill registry（`tenant.cjs` 的目录初始化 + 原生 `tool-skill`/`ctx.skills`），技术上是否可行、大致工作量。
2. **针对上面 5 个缺口**，哪些必须接入前补齐、哪些可以接入后再迭代，大致工作量。
3. 确认这件事**不影响 F1**——此前已经定了 reasoningEffort 不计入 F1 本期验收，媒体生成同样属于后续功能包，不是本期收尾范围内的事。
